# Meltype for Mac コード総点検 (2026-10-27、HEAD 8a54521 = v1.2.4)

対象: このリポジトリ の Mac 版に関わるコード全体 (Core = `src/Meltype.Core`、FFI = `src/Meltype.Mac.Native`、Swift = `mac/Sources`、配布スクリプト・ツール・テスト基盤)。Windows 本体 (`src/Meltype/`) と Linux は対象外。Core は 3 OS 共有なので、Core の指摘は Windows にも届く (表の「Core 共有」)。
目的: 不具合 (利用者が踏む形で書く)・改善できる点・機能改善につながるリファクタリング候補・テストの穴を、根拠つきで一覧にする。**修正はしていない** (この文書は点検の記録。直すときは `IMPROVEMENT_PLAN.md` に項目を立てて 1 つずつ)。
方法: 11 レーン (下の §1) が並列に読み、`--repro` と使い捨てテストで再現できるものは再現し、5 名の独立査読が「中」の全件と「低」の一部を再実行・再読して重大度と記録の照合を直した。その後、統合版をさらに別の査読者が確かめた (§付録 B)。すべて `delegate_task` の子 (この会話と同じモデル Claude Fable 5。`claude` CLI が未ログインで Opus への振り分けはしていない)。基準は `main` 8a54521 の読み取り専用 worktree で、Core テストは 1145/1145 合格。**実機 (TextEdit などで実際に打つこと) は誰もしていない**: Swift 側の指摘はすべて読取か推測で、「実機未確認」。

## 結論 (先に)

- **重大度「高」の問題はありません。** 「中」は 21 件 (不具合 7、堅牢性 4、改善 2、テストの穴 8)。「低」は 135 件 (§付録 A)。レーンの初版では「中」が 29 件ありましたが、独立査読で 8 件を「低」に下げました (既定 OFF の設定でしか起きない・該当者が開発者だけ・別のロックの話だった、など)。
- **いま直す価値が高い 6 件** (小さく直せて、利用者が踏む):
  1. 予測候補を確定すると、その「読み → 語」が変換の学習に入り、次からその読みの変換の最初の候補が乗っ取られる (`たんいを → 単位を取得する` の後、`tanniwotoru` Space が `単位を取得する取る`)。予測もライブ変換も既定 ON (§2 の 1)
  2. 設定「変換中の BackSpace で文節を消す」ON で、打ち直しが「日本語 + 英語」で終わると Space の確定で後ろの文節が消える (§2 の 2)
  3. 手で編集した config.json の 1 項目だけ型が違うと、全設定が既定値に戻る (§2 の 4)
  4. 「前の文脈ごとに分けて学習」ON で覚えた語は、辞書アプリから消しても消えない (成功と表示される) (§2 の 5)
  5. 辞書アプリの設定タブ・判定タブで ⌘Z を押すと、隠れたユーザー辞書/専門用語集タブの直前の操作が黙って取り消される (§2 の 6)
  6. 本体 (dylib) の版が合わないとき、IME が全キー素通しのまま利用者に何も知らせない (§3 の 2)
- **繰り返し出ている型** (リファクタリングの根拠。§6):
  - A. **状態のリセット漏れ**: 変換 1 回分の状態を戻す経路が 12 か所あり、それぞれ違う部分集合を戻す。上の 2 と、F6 → BackSpace で元の語が消える件 (§2 の 3) はこの型
  - B. **二重管理の食い違い**: 「表示の英字判定」と「確定時に直してよい文字」が別の規則 (K88 (3) の `_zoverdesu` → `_zovedesu` の原因)、読みの正規化が 4 実装、ホストへ確定文字を書く口が 11 か所、FFI の欄区切り文字列のパーサーが 3 か所、ライセンス一覧とビルド出力の一覧
  - C. **黙って失敗する**: ABI 不一致で通知なし、更新の展開失敗で原因が捨てられる、`0/0 passed` で exit 0、入力ファイル欠落で少ない語のまま辞書生成、削除が失敗しても成功表示
- **土台は堅い** (§7): 書き込みは全経路 `SafeFile` (一時ファイル → fsync → rename) + `FileLock` (flock)。FFI は 35 + 44 本の Swift 側シンボルと py の 51 本が Exports.cs と機械照合で**ずれ 0**、ABI 13 は 3 か所一致、Swift の `try!`/`as!` は 0 件。IMK のライフサイクルは `hideComposition` に集約されタイマー・世代番号の漏れなし。例外からの回復は Core (`Safely` → `Reset`) と FFI (`Run` → NULL) の 2 層。

## 7. 良い点 (具体的に)

- `_compositionId` で、遅れて返ってきた前の入力の surrounding text を 1 行で捨てている (非同期の取り違えの典型を防ぐ)。`Reset()` は例外復旧用に全フィールドを揃えて消し、`MeltypeSession.Safely` → FFI `Run` → Swift の `hideComposition` と 3 段で「落ちない・状態が残らない」が設計されている
- `TryToggleLastWord` は「読めない・一致しない・時間切れ」のすべてで何もせずキーを通す側に倒し、消す文字列 `expected` を必ず添える。Swift 側の照合 (NBSP を半角に揃える) と合わせて「文字が消える型」を二重に防いでいる
- `RomajiTable.Load` は FIFO・デバイス・シンボリックリンク先の種類・1 MB 上限・BOM・一時失敗の再試行まで、入力スレッドで安全に読む条件を網羅し、テストが機構を直接突いている
- `SpanTable` + `_spanCache` + 長さ上限 48 で日本語の長文は 816 文字でも 0.9 秒と頭打ち。`Detector_SkippingSpans_DoesNotChangeResults` が「最適化なしと途中経過まで完全一致」を見る等価テストになっている
- `UserDictionary.Mutate` は「プロセスをまたぐロック → 読み直し → 変更 → `.bak` → 置き換え保存 → 自分の版を採用」の順序が正しく、「読めないファイルには書かない」「書けなければメモリも変えない」が徹底。`HasUnsafeText` はコードポイント単位で制御文字・孤立サロゲートを弾き、ファイルから読む経路にも同じ検査が入る
- `LanguageMemory.Edit` は「ロック → 強制読み直し → 変更 → Trim → 保存、失敗なら戻す」を 1 か所にまとめ、`Remember`・`Undo`・`Set`・`Remove`・`Clear` がすべてそこを通る。損 (ロック無し保存の競合) もコメントに数字つきで書いてある
- `MacSettingsCatalog` は既定値を持たず `new Settings()` を参照し、説明文・選択肢は reflection で全項目を照合するテストがある。設定の既定値の三重管理は**存在しない** (L5 が全設定を照合)。`SafeFile` + `FileLock` は 2 プロセス書き込みの定石を正しく踏む
- FFI は Swift と py が参照する契約 (名前・引数の数と種類・戻り値) が Exports.cs と機械照合で一致。`learnCallback` は async の前に C 文字列を Swift の String にコピーしている。`DictionaryChange.perform` は部分失敗のたびに「それでも取り消せる undo」を返す。`install.sh` は「退避 → rsync → verify → 復元」を set -e に任せず明示的に処理し、`check-install-stop-ime.py` は身代わり実行ファイルで Q13 を再現して守っている
