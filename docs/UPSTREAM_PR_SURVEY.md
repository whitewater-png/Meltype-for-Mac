## 5. 査読で訂正された点

別の査読員が 12 件の主張を検証し、次を訂正した。

1. **`--repro` と実機の判定器のずれ** (最も重要)。`--repro` / `--expect` は同梱の単語表 (`BuiltInWordChecker`) を使い、実機は `NSSpellChecker` を使う。調査員は「現行では cwdde・pwdde が英字のまま」と報告したが、実機の判定器では現行ですでに `cwdで`・`pwdで` になる。#381 が実機で効くのは `gpgga`・`jwtto`・`tddde` のような NSSpellChecker が知らない語。**以後の検証は、BuiltIn と NSSpellChecker の両方で行う** (道具は作業用フォルダーに残したが 24 時間で消える。作り方は `meltype-mac-maintenance` の `references/upstream-issue-triage.md` に記録)。
2. **入力中の表示 (showing) と確定 (committed) の混同**。anata は確定がもとから あなた で、崩れるのは入力中の表示だけ。pingwoutsu は実機の判定器で、表示が pingをうつ・確定が ぴんがをうつ と食い違う。
3. **#308 は本家の差分が当たらない**。本家は `CompositionController` の `ControlShortcut(U/I/O/P)` に H を足す変更だが、Mac 版にそのコードが無い。Mac では `MeltypeSession.CtrlShortcutToFunctionKey` に足す別実装になる。
4. 「採用可」の一覧は、そのまま当たる PR (#381・#320・#314・#312・#384・#382・#383 のソース側) と、手で移植が要る PR (#385・#308・#321・#332) を区別していなかった。
5. 回帰の確認: 5,040 件のコーパスを、現行と各 PR 適用後で比べた。確定結果が変わったのは #381 が 9 件 (NSSpellChecker では 3 件)、#312 が 3 件、#320 が 3 件、#382 が 3 件で、#314・#384・#383 は 0 件。実在の日本語の語や文を壊した例は見つからなかった。品質評価 (`--eval-json`) は全 PR で 1242/1244 のまま。
