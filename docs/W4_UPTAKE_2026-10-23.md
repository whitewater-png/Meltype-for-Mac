## 本家の症状と、うちの直し方

本家 #1023 は「同じ語を、日本語の文脈では かな、英語の文脈では英字で出したい」という提案。Mac 版は **入力モードが 2 つ**ある:

- **英数 (直接入力)**: Core の変換ボックスを通らないので、`exe` はそのまま英字。**設定に関係なく今までどおり**。
- **日本語 (Meltype)**: Core の判定器を通る。ここだけが対象。

`exe` は本家 #895 で `dictionaries/english.txt` に足した語なので、今は日本語の文脈でも英字のまま (`これはexe`)。設定を ON にすると、**一覧の語**を「前が英語でない (日本語の続き・入力の先頭)」ときだけ英語と見ない。英語の文の中 (`hello exe`) と拡張子 (`.exe`) は今までどおり英字。

「語ごとのモード」を状態 (フラグ) で持つ案は捨てた: 設定タブで語ごとに切り替える UI が要り、入力中にモードを変えたときの持ち回しも壊れやすい。**語の一覧 + 1 つの設定**なら、状態を持たずに構造で決まる (前が英語かどうかは、そのつど区間の前後から判定する)。

## ON / OFF の実測 (テストと `--repro` で固定)

| 打った | OFF (今まで) | ON |
| --- | --- | --- |
| `exe` → Enter | `exe` | `えぇ` |
| `exe` → Space | `exe ` (確定) | 変換を開始。候補 `えぇ / エェ / ｴｪ / exe / ｅｘｅ` |
| `korehaexe` → Enter | `これはexe` | `これはえぇ` |
| `korehaexe` → Space | `これはexe ` (確定) | 変換を開始。候補 `これはえぇ / コレハエェ / … / korehaexe / …` |
| `exewo` → Enter | `exeを` | `えぇを` |
| `.exe` → Enter | `.exe` | `.exe` (拡張子は英字のまま) |
| `hello` → Enter | `hello` | `hello` (一覧に無い語は今までどおり) |
| `hello exe` → Enter | `hello exe` | `hello exe` (前が英単語なら英字のまま) |
| `exefairu` → Enter | `exeふぁいる` | `えぇふぁいる` (**トレードオフ**: すぐ続く かな があると語全体が かな になる) |

`exefairu` は「語の直後に かな が続く」形。一覧の語を「前が英語でない」だけで かな にするので、`exe` + `fairu` の境目を自動では分けられない。英語で出したいときは候補の `exe` を選ぶか、`exe` の直後に Space を打ってから続ける。この形を直すには「次がかな なら英語のまま」のような条件を足すことになるが、`exewo` (`えぇを`) のような自然な形まで英語に戻す危険があるので、今は入れていない。

## 実機で確かめること (実機確認待ち)

設定タブ「入力」→「日本語入力中は一覧の語をかなで変換」を ON にして、TextEdit で:

1. `exe` → Space: 候補の先頭が `えぇ` で、`exe` も候補にあること。
2. `exe` → Enter: `えぇ` で確定すること。
3. `.exe` → Enter: `.exe` のまま (拡張子は英字) であること。
4. `hello exe` → Enter: `hello exe` のまま (英語の文の中) であること。
5. 設定を OFF に戻して `exe` → Enter: `exe` に戻ること (再起動なしで次の打鍵から効く)。

`exewo` → `えぇを`、`exefairu` → `えぇふぁいる` も、余裕があれば一緒に見る (トレードオフの確認)。
