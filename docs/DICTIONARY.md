# 専門用語集の作り方 (`dictionaries/terms-*.txt`)

> **同梱の専門用語集はサンプルです。** 利用者が自分の用途に合わせて育てていくための出発点で、完成した辞書ではありません。不要な語は「除外」、直したい語は「直す」、使いたい語は「複製」、足したい語はユーザー辞書への登録で、自分の辞書にしていってください。 画面では「専門用語集(サンプル)」と表示します。

Meltype に、分野ごとの専門用語 (医学・法律・IT・数学など) を同梱するための手引きです。
語ファイルを `dictionaries/` に置いてビルドするだけで、**コードを変えずに**入力メニューの「専門用語集」に分野として並び、有効にすると変換と予測変換に反映されます。
配布はアプリの更新で行います (利用者が個別に追加するものではありません。利用者が自分で語を足すときは、ユーザー辞書を使います)。

## 0. 利用者向け: 分野ごとに入力メニューで切り替える

- Mac 版の入力メニュー (メニューバーの Meltype) の **「専門用語集」** に、同梱の分野が「名称 (語数)」で並びます。使いたい分野をクリックするとチェックが付き、その分野の語が変換・予測変換に使われます。もう一度クリックすると OFF に戻ります。
- **既定はすべて OFF** です。専門語は日常の文の変換にも混ざりうるため、必要な分野だけ有効にしてください。
- 切り替えはすぐに、すべての入力欄に反映されます (アプリを開き直す必要はありません)。
- 有効にした分野は `config.json` の `EnabledTermDomains` (分野の ID の一覧。例: `["civil", "it"]`) に保存され、次の起動でも保たれます。`config.json` が読めない (壊れている) ときは、上書きせず、切り替えを断って通知します。一覧にない ID は無視されます。
- Mac 版は、入力メニューの「辞書を管理…」で開く **「Meltype 辞書」** の「専門用語集」のタブでも切り替えられます (左の分野のチェック)。どちらで切り替えても同じ設定です。
- **Windows 版・Linux 版には切り替えの画面がありません。** 使うときは `config.json` の `EnabledTermDomains` を手で編集します (例: `"EnabledTermDomains": ["civil", "it"]`。反映は次回の起動から)。
- OFF の分野の語はメモリに読み込みません (メニューに語数を出すために一度数えるだけです)。

### 0.1 利用者向け: 同梱の語を使わない (除外)・直す・ユーザー辞書へ写す (Mac の「Meltype 辞書」)

同梱のファイルはアプリの一部で書き換えられないので、「Meltype 辞書」の「専門用語集」のタブでは、次の意味の操作になります。

| 操作 | 意味 | 保存先 | 元に戻す |
| --- | --- | --- | --- |
| 除外する (Delete) | その語を変換に使わない。強制型・候補追加型・予測変換のどれにも出なくなる | `terms-excluded.txt` | 「除外をやめる」・⌘Z。除外中の語は一覧に取り消し線と「除外中」で残る |
| 直してユーザー辞書へ (Return) | 元の語を除外し、直した語をユーザー辞書に登録する (直した語がもうユーザー辞書にあれば、除外だけ) | `terms-excluded.txt` + `userdict.txt` | ⌘Z で両方 |
| ユーザー辞書へ複製 | そのままユーザー辞書にコピーする (ユーザー辞書は最優先なので、確実に先頭に出したい語に) | `userdict.txt` | ⌘Z |

- `terms-excluded.txt` はデータフォルダ (`~/Library/Application Support/Meltype/`) の、1 行に「読み[Tab]語」(`#` の行はコメント)。`config.json` とは別のファイルにしています (数千行になりうるため)。保存は一時ファイルからの置き換え・本人だけが読める権限 (0600)。読めない (壊れた) ファイルは上書きしません。
- 除外は、読み (ひらがなにそろえたもの) と語の組で決まります。同じ組が複数の分野にあれば、全部の分野で除外されます。分野を OFF にしても除外は残ります (ON に戻したときも除外のまま)。
- 画面での変更は、動いている IME にすぐ反映されます (IME はファイルの版を 0.5 秒ごとに確かめて読み直す)。手で `terms-excluded.txt` を編集しても同じです (Windows 版・Linux 版も、動いている Meltype が読み直します)。

## 1. ファイル名と置き場所

- 置き場所: リポジトリ直下の `dictionaries/terms-<分野>.txt` (例: `terms-medical.txt`、`terms-law.txt`)。
- `dictionaries/` の直下に置くこと (サブフォルダーは不可)。`Meltype.Core.csproj` が `dictionaries/*.txt` をアプリに埋め込み、`terms-` で始まるものを分野として並べます (読み込むのは、利用者が有効にした分野だけです)。
- 文字コードは UTF-8 (BOM なし推奨)。改行は LF でも CRLF でも読めます。
- 分野の ID は、ファイル名から `terms-` と `.txt` を除いたもの (`terms-civil.txt` → `civil`)。設定にはこの ID を保存します。ID は変えないでください (変えると、利用者の有効にしていた設定が外れます)。
- 雛形: [`dictionaries/terms-template.txt`](../dictionaries/terms-template.txt) をコピーして使ってください (雛形自体は語を持たず、分野の一覧にも出ません)。

## 2. 形式

1 行に「読み`<Tab>`語`<Tab>`注記 (任意)」。区切りは **Tab** です (スペースではありません)。

```text
# 名称: 数学・医学
# 出典: 自作
# ライセンス: 自作 (GPL-3.0-or-later で提供)
ぎょうれつしき	行列式	数学
こうけつあつ	高血圧	医学
```

| 決まり | 内容 |
| --- | --- |
| コメント | `#` で始まる行と空行は読み飛ばす |
| 名称 | ファイルの先頭のコメントに `# 名称: 土木・建設` の行が**必須** (入力メニュー「専門用語集」に出る分野の名前。無いと検査がエラーで、アプリでは ID が名前になる) |
| 出典・ライセンス | ファイルの先頭のコメントに `# 出典: …` と `# ライセンス: …` の行が**必須** (無いと検査がエラー。自作なら「自作」でよい) |
| 読み | ひらがな (長音「ー」は可)。2 文字以上 100 文字以下。数字・英字・中点「・」・空白は不可 |
| 語 | 100 文字以下。改行・Tab は使えない |
| 注記 | 3 つ目の欄。読み込みでは使わない (メモ用) |
| 同じ読みに複数の語 | 行を分けて書く。先に書いた語が先に出る。20 語を超えると検査が警告する |
| 不正な行 | アプリは**飛ばすだけ** (例外にしない)。検査ツールで先に見つけておく |

読みにカタカナ・全角英数が来ても、アプリはひらがな・半角にそろえて読みます (`UserDictionary` の取り込みと同じ考え方)。ただし検査ツールはカタカナの読みをエラーにするので、ひらがなで書いてください。

## 3. 読みの長さで、変換への効き方が変わる

読みの文字数で、自動的に 2 種類に振り分けます (しきい値は `TermDictionary.ForcedMinReadingLength = 4`、コードの 1 か所)。

- **強制型 (読みが 4 文字以上)**: ユーザー辞書の組み込み語句と同じ。変換する読みの**中**にその読みが含まれていれば、その部分を語にします (`ぎょうれつしきをもとめる` → `行列式|を求める`)。長い読みは日常語の途中にたまたま現れにくいので、強制しても安全です。
- **語が ASCII だけ (英数字・記号のみ) の語は、読みが長くても候補追加型**: 強制すると日常語が英単語に置き換わるためです (例: IT 用語の `あいこん→icon`・`くりっく→click` を強制すると、「あいこんをくりっく」が「icon|を|click」になる)。候補・予測には出ます。
- **読みが日常語の読みと同じ語も候補追加型**: 読みが `dictionaries/readings.txt` (よく使う語の読み) の見出しと同じ語は、4 文字以上でも強制しません。強制すると、日常語の中に専門用語が割り込むためです (例: 映像の `こうせい→構成` を強制すると、「こうせいろうどうしょう」が「構成|ろうどうしょう」になる。`かいてん→回転` は「きかいてんけん」の途中に当たる)。候補・予測には出ます。日常語と同じ読みでも文の中で固定したい語は、**4 つ目の欄に `強制` と書きます** (`読み<Tab>語<Tab>注記<Tab>強制`。注記が無いときは `読み<Tab>語<Tab><Tab>強制`)。
- **候補追加型 (読みが 3 文字以下)**: 変換候補に**足すだけ**で、強制しません (文節の区切りも変えません)。短い読み (`すう`、`ひと` など) を強制すると、日常の言葉の途中にも現れて誤変換を招くためです。そのかわり、候補の先頭には出ないことがあります。短い語を確実に先頭にしたいときは、ユーザー辞書に登録してください。

**日常語と衝突する語の一覧**は `node tools/check-terms.mjs --collisions` で出せます (ファイル:行 読み→語)。印を付ける語は、この一覧から選んでください。

**4〜5 文字の読みは一般の語と重なりやすい**ので、強制型でも巻き込みが起きることがあります。実データ (実際に打って変換) で確認してください。検査ツールは、読みがちょうど 4 文字の語を件数と先頭数件つきで情報として出します。

どちらの語も、予測変換 (読みの前方一致) に出ます。

## 4. 優先順位

ユーザー辞書 (`userdict.txt`、最優先) > 専門用語集 > 変換エンジン。

- 同じ読みでユーザー辞書に登録があれば、そちらが先です。読みの長さが違うときは、長い方の読みが先に使われます (最長一致)。
- 専門用語集は**ユーザー辞書の保存・表示・書き出しに混ざりません** (組み込み語句 `phrases.txt` と同じ扱い)。利用者のユーザー辞書の画面に数万語が出ることはなく、`userdict.txt` にも書き込まれません。
  (「Meltype 辞書」の「直す」「複製」で、利用者が選んだ語だけがユーザー辞書に入ります。)
- 利用者が除外した語 (`terms-excluded.txt`) は、どの順位にも出ません。
- 予測変換の並びは、ユーザー辞書 → 専門用語集 → 変換エンジン → 変換履歴 (重複は除く)。

- **辞書提案との関係**: 強制型の専門用語は「登録済み」の判定に含まれる (辞書への登録の提案から除かれる)。候補追加型は含まれないので、同じ語が提案されることがある。

## 5. 出典とライセンスの扱い (必ず守ること)

Meltype は GPL-3.0-or-later です。次を守ってください。

- **ATOK・Microsoft IME・Google 日本語入力など、市販・既存の IME の辞書の内容を写さない。** 書き出しファイルを加工して入れることも同じく不可です。
- **AI で作る場合は、読みと語を人が 1 語ずつ確認する。** AI は読みや用語を取り違えることがあり、既存の辞書の内容を再現してしまうこともあります。確認できない語は入れません。
- **他人の用語集・データを使うときは、権利を確かめる。** 使ってよいライセンス (自作、CC0、CC BY など GPL と両立するもの) だけを使い、ファイルの先頭に `# 出典:` `# ライセンス:` を書きます。派生して作るスクリプトがあれば `tools/` に置きます。
- 出典は [`THIRD-PARTY-NOTICES.md`](../THIRD-PARTY-NOTICES.md) の「専門用語集」の表にも追記してください (自作でも、ファイル名と「自作」を書く)。

## 6. 検査のしかた

```bash
node tools/check-terms.mjs                       # dictionaries/terms-*.txt をすべて検査
node tools/check-terms.mjs dictionaries/terms-medical.txt   # 1 ファイルだけ
node tools/check-terms.mjs --self-test           # 検査ツール自身のテスト
```

- **エラー** (終了コード 1): 名称・出典・ライセンスの行が無い、欄の数が違う、読みがひらがな以外・2 文字未満・100 文字超、語が空・100 文字超。
- **警告**: 同じ読み+語の重複、同じ読みに語が 20 を超える、欄の前後の空白、語が読みと同じ、BOM。
- **警告 (追加)**: 名称・出典・ライセンスの行が雛形の「(例: …)」のまま語が 1 つ以上ある。強制型になる語の読みが日常語の読みと同じ (候補追加型に落ちる件数と例を出す。全件は `--collisions`)。強制型にならない語に `強制` の印がある (効果がない)。
- **エラー (追加)**: 4 つ目の欄が `強制` 以外。欄の数は 2〜4 個。
- **情報**: 読みがちょうど 4 文字の語 (巻き込みに注意)、読みが 3 文字以下の語は「候補追加型」になる件数。総語数・強制型の数。

エラーが 0 になってから置いてください。なお、`tools/check-dictionaries.mjs` は `terms-*.txt` を対象にしません (こちらの検査ツールが担当します)。

## 7. 読み込みの確認 (テスト)

```bash
~/.dotnet/dotnet run --project src/Meltype.Core.Tests -- Terms_      # 読み込み・振り分け
~/.dotnet/dotnet run --project src/Meltype.Core.Tests -- TermDomain   # 分野の切り替え・保存
```

`src/Meltype.Core.Tests/TermDictionaryTests.cs` が、読み込みの形式・強制型 / 候補追加型の振り分け・ユーザー辞書の優先・不正行の無視・予測への表示・保存への非混入・5 万語の規模 (読み込み時間・メモリ・1 キーの時間) を確かめます。
自分の語ファイルが分野として見えているかは、`TermDomains.List()` (名称・語数) で分かります (ビルドし直すと埋め込まれます)。分野の切り替えと保存は `src/Meltype.Core.Tests/TermDomainTests.cs` が確かめます。変換の動きは、Mac 版を入れ替えて実際に入力して確かめてください。
