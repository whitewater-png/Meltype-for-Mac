# 変換精度で本家に追いつき、越えるための計画 (2026-11 版・案)

状態: **案**。§7 の判断をリョウさんにお願いしてから動かす。作成 2026-11-22。

- 「変換精度」は 2 つを指す: (1) 日英判定 (ローマ字を かな にするか、英字のまま残すか)、(2) かな漢字変換。
- Mac 版の数字は、1.2.8 (`20736db`) を 2026-11-22 にクラウドの Linux で回した実測 (Core のテスト用キーボード。azooKey も実機の入力欄も使わない)。本家の動きは、本家のリリースノート (2026-11-22 に取得。§10)。
- 推測は「(推測)」、確かめていないことは「(未確認)」と書く。この文書を作る作業では、実機 (Mac の入力欄・azooKey・Zenzai) で確かめたことは 1 つも無い。
- 生きている数字は [AGENT_STATE.md](AGENT_STATE.md) と [COMPARISON_UPSTREAM.md](COMPARISON_UPSTREAM.md) に書く。ここの数字は 2026-11-22 の控え。

## 0. 要約

1. 本家は 2 週間で変換の土台を替えた (§1.1)。v1.5.0 (11/08) で Zenzai を同梱して既定 ON にし、日英の境界判定を作り直した (複数の区切り方の点数を比べる)。v1.6.0 (11/14) で漢字変換を全 OS で Mozc + Zenzai にした (Mac の azooKey をやめた)。v1.7.0 (11/20) で英単語の判定を全 OS で同梱の単語の一覧にした。v1.7.1 (11/21) で入力欄の文脈をそのまま変換エンジンに渡すようにした。
2. 戦略計画 ([STRATEGY_2026-10.md](STRATEGY_2026-10.md)) の柱 C「変換精度で先行する」は、もともと限定付きで、先行の価値を Zenzai を使えることではなく「Zenzai × 日英判定の統合」と「計測結果」に置いていた。統合の実験 (2-1) は no-go で、本家は Zenzai を既定 ON で配り始めたので、この柱は前提から立て直しが要る。既定の設定で利用者が受け取る漢字変換は、本家 = Zenzai ON・文脈あり、Mac 版 = Zenzai OFF・前の文が渡らない (Q43)。同じ表で比べた数字は無い (未計測) が、既定どうしでは Mac 版が下回っている可能性が高い (推測。根拠は Mac 版自身の計測で、Zenzai OFF 69.3 % / ON 86.3 %)。
3. 日英判定は、同じ正解表で Mac 版 622/728・本家 551/728 (11/11、本家 1.5.0)。ただし表の大半は Mac 版が自分で足した作例で、本家の表 (`upstream-quality`) では 186/203 対 201/203 と下回る。その本家の表も 10/13 の写し (203 件) のままで、本家の品質テスト (11/11 に 1383 件) の新しい分は一度も取り込んでいない。
4. 本家追従は 10/28 の seen (`a2d74f0`) で止まっている。11/11 時点で 874 コミットが未分類で、v1.5.0〜1.7.1 の中身も分類していない。
5. 残っている判定の外れは、辞書に 1 語足すだけではもう直らない型が中心 (英文の後の短い語・や + 英単語・英字のあいだの と・数字を挟む略語など)。判定ロジックを変えるための「大量の境界例で悪化を測る道具」は、リポジトリに無い (独立査読の手元にだけある)。
6. 進め方: Phase 0 公平な物差しを作る → Phase 1 漢字変換の既定を本家に追いつかせる → Phase 2 判定の差を詰める (本家の新しい境界判定を今の版で測り直してから方式を決める) → Phase 3 Mac で打つ文で越える。
7. 全面で本家を越えるのは、開発の速さとコミュニティの差から現実的ではない (推測)。越える狙いは 3 つに絞る: Mac で打つ文 (技術・AI ツール・ターミナル・日英混在) の判定と変換、文脈つきの学習、測り方の透明さ。
8. 人に決めてほしいことは 6 件 (§7)。いちばん大きいのは、「悪化ゼロ」の決まりを大きな方式変更にどう当てるか。

### 1.3 Mac 版のかな漢字変換

- 構成: azooKey (コミット `d59a28e4` に固定、Zenzai は CPU 版) ([mac/Package.swift](../mac/Package.swift))。Zenzai は設定で ON にでき、**既定 OFF** ([Settings.cs](../src/Meltype.Core/Config/Settings.cs) の `Zenzai`)。ON にしたときだけ、重み (zenz-v3.1-small、約 74 MB) を Hugging Face から取得する ([README.md](../README.md) の通信の節、[THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md))。推論の上限は 3。1 キー 300 ms 超が 3 回続くと、そのプロセスでは Zenzai を使わなくなる ([Converter.swift](../mac/Sources/MeltypeIME/Converter.swift) の `zenzaiInferenceLimit`・`zenzaiSlowSeconds`)。
- 計測 (212 文、第一候補の一致、M4 Max、2026-10-14): Zenzai なし 147 (69.3 %) → ON・左文脈なし 183 (86.3 %) → ON・左文脈あり 193 (91.0 %)。1 キーの p95 は 7.3 ms → 61.0 ms ([ZENZAI_EXPERIMENT_2026-10.md](ZENZAI_EXPERIMENT_2026-10.md) の結論表)。
- ただし「左文脈あり」は前の文を直接渡した値で、製品では出ない。製品は前の文が「。」で終わると文脈が空になる。前の文で決まる 32 行では Zenzai ON でも 14/32 (OFF と同じ) で、前の文を渡すと 24/32 ([UPSTREAM_PR_TRACKER.md](UPSTREAM_PR_TRACKER.md) の Q43。実エンジンの計測、実機は未確認)。
- 学習の穴 (どれも判断待ち・実機未確認): ライブ変換の表示のまま Enter で確定すると、漢字の学習が更新されない (Q41)。読み → 語だけの選び直しの記録が、Zenzai の文脈の判断に勝つ (Q42)。
- 正解表の限界: 212 文のうち 142 文は LLM が作った教科書的な文で、**日英混在の文は無い** (ZENZAI_EXPERIMENT_2026-10.md の信頼度の注記)。計測のコードは手元のブランチ (`exp/zenzai-1-1`) だけにある。製品の経路で一致数を出す自己テスト (`--zenzai-self-test --cases`) はある (eval/README.md)。
- M1 級・メモリ 8 GB の Mac では速さを測っていない ([KNOWN_LIMITS.md](KNOWN_LIMITS.md) の K67)。
- **本家とかな漢字変換を比べた数字は無い** (COMPARISON_UPSTREAM.md §2 の「判定精度 4」は未計測)。

## 7. 判断をお願いしたいこと

1. **順番**: 漢字変換の既定 (Phase 1) を、判定の方式 (Phase 2) より先に進めてよいか。→ 推奨: はい。本家との差が開いた主な理由は漢字側の土台の変化で、Q41・Q43 は Core の小さな変更で済む見込み (推測)。
2. **「悪化ゼロ」の当て方**: 大きな方式変更 (2-2 の B・C、エンジンの変更) にも、1 件の悪化も許さない今の決まりを当てるか。要件 007・009 の見送りと、#1185 の「導入しない」は、どれもこの決まりによる判断だった。→ 推奨: 保護区間 (パス・オプション・URL) と日本語の文の崩れは 0 のまま。それ以外は、中立の表と本家の表で差し引きの改善が大きいときに限り、壊れる行を一覧にして、人が「受け入れる変化」として決める (要件 010 と同じやり方)。
3. **Zenzai の既定** (前の決定の再検討: 2026-10-15 の「既定 ON はしない」、STRATEGY_2026-10.md §8 の 4「重みは設定で ON にしたときだけ取得、配布物は今のまま」、§6「重みの取得は ON にしたときだけの通信に限る」): (a) 同梱して既定 ON (本家と同じ。§8 の 4 を覆す。配布物が約 74 MB 増える (推測: 重みは圧縮がほぼ効かない)。重みを再配布するので CC BY-SA 4.0 の表示が要る)、(b) 既定 ON にして初回に取得 (§6 を覆す。利用者が何も選ばないうちに通信が始まるので、通信の説明を変える)、(c) 既定 OFF のまま、初回に 1 回だけ案内する (前の決定の範囲)。→ 推奨: (a)。ただし M1 級の Mac で 1 回測れることを条件にし、測れないうちは (c)。**M1 級の Mac が手元にあるか** も教えてほしい。
4. **判定の方式** (2-2 の A・B・C)。→ 推奨: 2-1 の結果を見てから決める (今は決めない)。
5. **本家追従を回す場所**: (a) リョウさんの Mac で週 1 回 `upstream_watch.py` を回して push する、(b) Claude Code の Remote Control (Claude のデスクトップアプリ、またはターミナルの `claude remote-control`) で、Mac のフォルダーをクラウドのセッションから使えるようにし、AI が Mac の上で回す (Mac が起きている間だけ。使えるかと条件は、使う時点の案内で確かめる)。→ 推奨: (b)。Mac の上で回るので、クラウドから本家に届かない制約 (CLAUDE.md §2) を避けられ、人の手間も少ない。共有するのはこのリポジトリと本家の clone のフォルダーだけにし、学習データやトレースのある場所は含めない (トレースは打った文字が残る。CLAUDE.md §1)。
6. **英単語の語彙** (2-4): 実機も同梱の一覧に揃えるか。→ 推奨: 2-1 と同時に実機で並べて決める (今は材料が無い)。
