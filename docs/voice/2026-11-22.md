## 要件定義書の候補
既存の要件 (main の 001〜024、PR #29 の 015〜018 案)、10-24〜11-21 の文書の候補、`eval/cases/` (`anti`・`side`・閉じクォートの行は無い) と突き合わせた。

1. **`antigravity`・`sideload` のように、かなに読める接頭辞 (`anti`・`side`) と英単語がつながった語が、かなと英字に割れる問題を直す** (本家 #2193・#2200、どちらも Mac の利用者の報告) — scope: core (と、辞書で済むなら dictionary)
   - 背景: fork でも `あんちgravity`・`しでload` と割れ、`antivirus`・`sidebar`・`sidecar` など同じ形が広く起きる。11-19 の `pazolite` → `ぱぞlite` (要件 021) と似た「語の前半だけかな」の形。
   - minimum 要件: `anti`+英単語・`side`+英単語の形を、英字のまま残す。`anti`・`side` を単独で打った形 (`antiwo` など) と、`sidewo`・`sidenisuru` のような日本語の文の形を壊さない。辞書に語を足すか、判定で接頭辞を扱うかは調査で決める。
   - 完成条件の案: 正解表に `antigravity`・`antivirus`・`sideload`・`sidebar` を英字の期待で足し、直す前は外れ・直した後は当たる。かなの形 (`sidewo` などを今の出力で) を守る行も足す。Core 全件通過、eval-compare の broken 0。判定に触るなら査読員が境界例を作って base と比べる。

2. **日本語を挟んだ引用符の組 (`'…'`・`"…"`) を崩さない** (本家 #2221) — scope: core
   - 背景: fork でも `printf('konnnitiha')` → `printf('こんにちは’)` と、閉じだけ全角になる。コードの文字列やメモで日本語を引用符で囲むと、組が合わなくなる。
   - minimum 要件: 開きの引用符が半角なら、閉じも半角にする (少なくとも組をそろえる)。`sore'desu'` → `それ’です’` のように両方全角になる形を変えるかは人が決める。縮約形 (`don't`) と `L'Arc` の今の形は守る。
   - 完成条件の案: 正解表に `printf('konnnitiha')`・`printf("konnnitiha")` を組の合った期待で足し、直す前は外れ・直した後は当たる。英語だけの `printf('hello')` と既存の `'` の行は broken 0。Core 全件通過。前回の候補 3 (括弧の幅) と記号の幅の決め方がつながるので、同じ要件で扱うかは人が決める。

3. **本家 11-22 の誤判定の形を、fork の今の出力で正解表に守る行として足す** — scope: core (正解表とテストだけ。判定ロジックは変えない)

   - minimum 要件: 上の形を今の出力 (`せっていしているんだけど`・`たいおうしているんだけど`・`mainかんすう`・`@exampleabc-jh.ed.jpdesu`) で `eval/cases/` に足す。漢字の形は扱わない。
   - 完成条件の案: 足した行が今の main で当たる。わざと崩した版で外れることを一度確かめる。Core 全件通過、eval-compare の broken 0。
