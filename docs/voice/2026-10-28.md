## 要件定義書の候補 (3 件まで)
既存の要件 001 (done)・002 (`ost`)・003 (長文が全部かな) と重ならないことを確かめた。

1. **かなの直後の `:`・`;` を全角にする (`tasuku:1kenn` → `たすく：1けん`)**
   - 背景: 本家 #637。fork の Core でも再現し、`,`・`.`・`?` は全角になるのに `:`・`;` だけ半角のまま残る。
   - minimum 要件: かなの直後に打った `:` が `：` で確定する。数字の間 (`10:30`)・URL (`http://`)・英語の区間の `:` は半角のまま。
   - 完成条件の案: 正解表に `tasuku:1kenn` → `たすく：1けん` などを足して赤を確かめ、直したあと ok。`kaigiha10:30kara`・`http://example.com`・英文の `Note: ...` が変わらないことも行で守る。回帰ゲートの broken 0。
   - scope: core (本家の作者は「設定で選べるように」とも書いている。設定を足すなら設定のファイル形式に及ぶので、`CLAUDE.md` §5 により人の判断を仰ぐ)
2. **同梱語句の最長一致で、語の途中の読みが切り出されないようにする (`ishokujoutai` → `い食事ょうたい`)**
   - 背景: 本家 #1262。fork にも同じ `Split` と `phrases.txt` の `しょくじ` があり、同じことが起きる可能性がある (推測)。
   - minimum 要件: まず Core で、`ishokujoutai` を変換したとき `phrases.txt` の `しょくじ` が切り出されるかを測る。切り出されるなら、拗音の途中 (`じ` + `ょ`) で区切らない。
   - 完成条件の案: Core のテスト (`UserDictionary` の `Split` に `いしょくじょうたい` を渡し、`しょくじ` が 1 つの区間にならない) を足して赤 → 緑。既存の `UserDictionary` のテストが全部通る。変換エンジンに任せる大きな作り替え (本家の提案そのもの) は非目標。
   - scope: core
3. **外のツール (Neovim のプラグインなど) から Meltype の日本語/英数が見分けられるか確かめる**
   - 背景: ime-auto.nvim PR #66 で、本家 Meltype は日本語中も ASCII を打てる入力ソースに見え、英数との区別ができないと書かれた。fork は 2 つのモード ID を持つが、外からの見え方は未確認。
   - minimum 要件: 実機で、日本語・英数を切り替えたとき `TISCopyCurrentKeyboardInputSource` の ID と ASCII を打てるかの値がどう変わるかを記録する。区別できなければ直す案を出す。
   - 完成条件の案: 実機チェックリスト (日本語 → 英数 → 日本語で、上の 2 つの値を記録。英数キー・かなキー・入力メニューの 3 通り)。結果を `docs/KNOWN_LIMITS.md` に書く。Core では測れない。
   - scope: swift (入力ソースの登録と IMK の経路なので、`CLAUDE.md` §5 により人に渡す前提)
