## 要件定義書の候補
既存の要件 001〜004、PR #10 (005 `beep`)・#11 (006 `^`)、10-24〜11-02 の文書の候補とは重ならないことを確かめた (`alma`・`pre`・`dissatisfactio`・番号を過去の文書と `eval/cases/` で `grep`、該当なし)。

1. **打っている間は `alma` と見えるのに、Enter で `あおま` が確定する (表示と確定のずれ)** — scope: core
   - 背景: 本家 #1487 を確かめる途中で、fork の Core では表示 (`alma`) と確定 (`あおま`) が食い違うと分かった。見えているものと違う文字が入るので、気づかずに送ってしまう。本家 main では `alma` のまま。
   - minimum 要件: `alma`・`almaga` で、Enter で確定する文字が直前の表示と同じになる (どちらに揃えるか — 英字のままか、かなか — は人が決める。`l` が `お` になる読みは無くす)。`salmon`・`almond`・`calm`・`elm` の今の値 (英字のまま) は変えない。
   - 完成条件の案: Core のテストに「`--repro` の `showing` と `committed` が同じ」を `alma`・`almaga` で足して実装前は赤・実装後は緑。正解表に `alma` と守る行を足す。Core 全件通過、eval-compare の broken 0。判定や確定の処理を変えるなら、同じずれが他の語で起きないかを査読員が境界例を作って base と比べる (`CLAUDE.md` §4)。

2. **`pre` がかなに崩れる (`pre` → `pれ`)** — scope: dictionary
   - 背景: 本家 #1489 (Windows、Discord)。fork の Core でも同じで、`prekana` も `pれかな`。本家の main では直っている見込み。要件 002 (`ost`)・005 (`beep`) と同じ「辞書に無い短い英字が崩れる」形。
   - minimum 要件: `pre` (単独・後ろに空白や助詞が続く形) が英字のまま残る。`preview`・`pre-release` は英字のまま、`pu`・`re` を使う日本語 (査読員が `--repro` で今の値を取ってから決める) は変えない。
   - 完成条件の案: 正解表に `pre` と守る行を足し、実装前は外れ・実装後は当たる。eval-compare の broken 0、Core 全件通過、`node tools/check-dictionaries.mjs` が通る。**本家の直し方を Mac 側で見て、取り込みで済むかを先に確かめる。**

3. **英単語を打っている途中 (`dissatisfactio`) で頭がかなに崩れる** — scope: core
   - 背景: 本家 #1482。最後の `n` を打つ前の `dissatisfactio` が `ぢっさちsふぁcちお` になり、打ち終えると `dissatisfaction` に戻る。fork でも同じで、打っている間の表示がちらつく。
   - minimum 要件: 辞書にある長い英単語の途中 (例: `dissatisfactio`・人が選ぶ数語) で、Enter で確定したときに英字のまま残る。日本語として読める打ち方 (`dissatsu` のような形。査読員が今の値を取ってから決める) は変えない。
   - 完成条件の案: 正解表に途中の形と守る行を足して、実装前は外れ・実装後は当たる。eval-compare の broken 0、Core 全件通過。判定ロジックを変えるので、日本語の打ちかけの形への回帰を査読員が境界例を作って base と比べる。
