## 要件定義書の候補
既存の要件 001〜010 (009 は PR #14、010 は PR #15)、10-24〜11-06 の文書の候補と突き合わせた。`colab`・`collab`・`kaggle`・`最後の文節` は過去の文書・`docs/requirements/`・`eval/cases/` で `grep` して該当なし。

1. **`colab`・`collab` が `こlab`・`こっlab` になる** — scope: dictionary
   - 背景: 本家 #1607。fork でも `colab` → `こlab`、`collab` → `こっlab`。Google Colab を使う人が毎回打ち直すことになる。`gitlab` は辞書 (`english.txt`) にあるので崩れない。
   - minimum 要件: `colab`・`collab` を英字のまま残す (辞書に足す)。`kora`・`korabo` のようなかなの語の今の値は変えない。
   - 完成条件の案: 正解表に `colab`・`collab`・`colabde` (`colabで`) と守る行 (`korabo` → `こらぼ`、`kore` → `これ`) を足し、実装前は外れ・実装後は当たる。Core 全件通過、eval-compare の broken 0。

2. **`kaggle` が `かっがぇ` になる** — scope: dictionary
   - 背景: 本家 #1609。fork でも `kaggle` → `かっがぇ`、`kagglede` → `かっがぇで`。読み `かぐる` からは `Kaggle` が出るが、英字で打った人には届かない。
   - minimum 要件: `kaggle` を英字のまま残す (辞書に足す)。`kagge…` で始まるかなの語 (`kagge` のような形) が今どうなるかを `--repro` で取ってから、変えないものを人が決める。
   - 完成条件の案: 正解表に `kaggle`・`kagglede` (`kaggleで`) と守る行 (`kaketa` → `かけた` のような `ka` 始まりのかなの語) を足し、実装前は外れ・実装後は当たる。Core 全件通過、eval-compare の broken 0。候補 1 と 1 つの要件にまとめてもよい (人が決める)。

3. **Space で変換したとき、最後の文節を選んだ状態で始める設定** — scope: core (設定を足すなら swift も)
   - 背景: 本家 #1620 (提案、全 OS)。長い文を打って最後の文節だけ直したいとき、→ を何度も押すことになる。fork も最初の文節を選んで始める作り (推測、実機は**未確認**)。
   - minimum 要件: 設定 (既定は OFF) が ON のとき、Space で変換を始めると最後の文節が選ばれる。OFF のときは今と同じ。
   - 完成条件の案: Core のテストに「ON で `kyouhatenkigaiikara` + Space → 選ばれた文節が最後」「OFF で今どおり最初」を足し、実装前は赤・実装後は緑。Core 全件通過、eval-compare の broken 0。設定のファイル形式・Swift の設定画面に手が入るので、要件にする前に人が範囲を決める (CLAUDE.md §5)。数字キーで候補を選んだときの確定の範囲 (本家 #1620 の作者も迷っている点) も人が決める。
