## 要件定義書の候補
既存の要件 001〜008、PR #10〜#13、10-24〜11-04 の文書の候補とは重ならないことを確かめた (`2nd`・`\n`・`ぼt` を過去の文書・`eval/cases/`・`docs/requirements/` で `grep`、該当なし)。候補 3 は 11-03 の候補 1 (`alma` の表示と確定のずれ) と同じ種類のずれを、語ごとではなくまとめて見る案。

1. **`2nd`・`22nd` が `2んd` になる (数字 + 序数の `nd`)** — scope: core
   - 背景: 本家 #1562。fork では `2nd`・`22nd`・`kyouha2nd` が `2んd` になる。`1st`・`3rd`・`4th` は英字のまま残るので、`nd` だけ崩れる。本家 main では bot が再現しなかった。
   - minimum 要件: 数字の直後の `nd` (`2nd`・`22nd`・`52nd`) を英字のまま残す。数字の直後の `nde`・`ndesu` (`2nddesu` など、かなに続く形) の扱いと、数字の付かない `nd` は今の値を `--repro` で取ってから人が決める。
   - 完成条件の案: 正解表に `2nd`・`22nd`・`kyouha2nd` と守る行 (`1st`・`3rd`・`4th`・`ni2nde` のようなかな + 数字の形) を足し、実装前は外れ・実装後は当たる。Core 全件通過、eval-compare の broken 0。数字の後ろの判定に触るので、`2ninn` (2人) のような数字 + `n` で始まる日本語への回帰を査読員が境界例を作って base と比べる。

2. **`\n` が表示は `\n` なのに Enter で `\ん` が確定する** — scope: core
   - 背景: 本家 #1543 (本家は `￥ん`)。fork では打っている間は `\n` と見えるが、Enter で末尾の `n` が `ん` になる。`\r\n` も同じ。コードや文章に改行の書き方を打つ人が困る。
   - minimum 要件: `\` の直後の英字 1 字 (`\n`・`\r\n`) を、Enter で確定しても表示どおり英字のまま残す。`\t`・`printf\n`・`\\` の今の値 (英字のまま) は変えない。
   - 完成条件の案: Core のテストに `--repro` の `showing` と `committed` が同じになることを `\n`・`\r\n`・`kaigyouha\nde` で足して実装前は赤・実装後は緑。正解表にも足す。Core 全件通過、eval-compare の broken 0。

3. **表示と確定がずれる語を正解表全体で洗い出す検査を足す** — scope: core
   - 背景: 11-03 の `alma` (表示 `alma`・確定 `あおま`) に続き、今回 `\n` (表示 `\n`・確定 `\ん`) と `bot` (表示 `ぼt`・確定 `bot`) でも食い違いが見つかった。見えている文字と違う文字が入ると、気づかずに送ってしまう。1 語ずつ見つけるより、まとめて見る方が早い。
   - minimum 要件: 正解表の全行について、Enter の直前の表示と確定が食い違う行の一覧を出す道具 (またはテストの出力) を作る。食い違いを直すかどうかは一覧を見て人が決める (この要件では直さない)。
   - 完成条件の案: 一覧を出す処理を足し、`alma`・`\n`・`bot` が一覧に出ることをテストで確かめる。既存のテスト・正解表の結果は変えない (Core 全件通過、eval-compare の broken 0)。
