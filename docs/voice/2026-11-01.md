## 要件定義書の候補
既存の要件 001〜004 と、PR #10 の 005 (`beep`) と、前回までの候補 (`docs/voice/2026-10-24`〜`10-31`) とは重ならないことを確かめた (`beep` とは別の語)。

1. **Unix のコマンド名 `stat`・`inotify` がかなに崩れる (`statsuruno` → `sたつるの`、`inotify` → `いnotify`)** — scope: dictionary
   - 背景: 本家 #1389・#1390 (Linux) と同じ形が fork の Core でも外れる。Mac のターミナルでも `stat` は使うコマンドで、要件 002 (`ost`) と同じ「辞書に無い短い技術語がローマ字として読める」形。
   - minimum 要件: `stat`・`inotify` と、その後ろに助詞・`suru` が続く形 (`stat suru`・`statsuruno`・`inotify ga`) が英字のまま残り、`inochi`・`inoti`・`sutato` などの日本語は変わらない (今の値: `inochi`・`inoti` → `いのち`、`inochiwo` → `いのちを`、`sutato` → `すたと`)。
   - 完成条件の案: 正解表 `eval/cases/mac-terminal.tsv` に上の外れる形と守る行を足し (書く前に `--repro` で外れることを確かめる)、実装前は外れ・実装後は当たる。eval-compare の broken 0、Core 全件通過、`node tools/check-dictionaries.mjs` が通る。

2. **`c` を使った英単語の綴りがかなに崩れる (`american` → `あめりかん`、`american megatrends` → `あめりかんめがtrends`)** — scope: core (辞書で直すなら dictionary)
   - 背景: 本家 #1391 (Windows、US 配列)。fork でも `ca` を「か」と読むため `american` が全部かなになり、空白で区切った `american express` でも頭がかなのまま。
   - minimum 要件: `american` (単独・後ろに英単語が続く形) が英字のまま残り、`k` で打った `amerikan` は `あめりかん` のまま (今の値: `amerikan` → `あめりかん`、`amerikan na` → `あめりかんな`)。
   - 完成条件の案: 正解表に `american`・`american megatrends`・`american express` と、守る `amerikan`・`amerikan na` を足して実装前は外れ・実装後は当たる。eval-compare の broken 0。判定ロジックを変えるなら、`ca`・`co`・`cu` を含む日本語の打ち方 (査読員が実データから作る) への回帰を、査読員が境界例を自分で作って base と比べる (`CLAUDE.md` §4)。なお `cocoa` は今も英字のまま (`--repro cocoa` → `cocoa`)。

3. **学習データの消去の確認で、消える件数を出す** — scope: swift (件数を数える処理は core)
   - 背景: 本家 #1386 の提案 (確認で件数が分からない)。Mac の「学習データをすべて消去…」は確認・完了のどちらにも件数を出さない。
   - minimum 要件: 確認のダイアログに、消える学習データの件数 (数えられる範囲で、種類ごとか合計) を出す。消す中身と既定のボタン (キャンセル) は変えない。
   - 完成条件の案: Core に件数を返す処理を足すならそのテスト (件数が実データと一致)、残りは実機チェックリスト (学習させてから入力メニューで消去 → 確認に件数が出る → 消去後にもう一度開くと 0 件)。**`InputController.swift` と学習データに触れるので `CLAUDE.md` §5 の止める条件に当たりうる。人が実機で確かめる前提。**
