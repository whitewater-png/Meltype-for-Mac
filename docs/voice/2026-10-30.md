## 要件定義書の候補 (3 件まで)
既存の要件 001 (done)・002 (`ost`)・003 (長文が全部かな) と、前回までの候補 (人名・打ちかけの表示・`:` の全角・同梱語句の最長一致・入力ソースの重複・Home/End・ユーザー辞書の取り込みのパネル・macOS 27 で入力ソースを戻す・カッコの中へカーソル・本家 PR #1185 の測定 など) と重ならないことを確かめた。今回の声で要件になりそうなのは本家 #1349 の 1 系統だけで、原因が違いそうな 2 つに分けた。3 件目は出していない (今回の他の声は fork に当てはまらないか、具体例が無い)。

1. **日本語の直後の、ハイフンでつないだ英語の `-` が長音になる (`kyouhagit-log` → `きょうはgitーlog`)**
   - 背景: 本家 #1349。fork の Core でも、`git-log`・`docker-compose`・`npm-run`・`e-mail` は単独なら英字のままだが、日本語の直後に続けると `-` が ー になり、後ろも崩れることがある (`きょうはnpmーるん`・`きょうはえーmail`)。
   - minimum 要件: 日本語の直後でも、単独のときに英字のまま確定する `英語-英語` の形は、`-` を含めて英字のまま確定する。`kyouhara-menwotaberu` (きょうはらーめんをたべる) のような長音は崩さない。
   - 完成条件の案: 正解表に `kyouhagit-log`→`きょうはgit-log`、`kyouhadocker-compose`→`きょうはdocker-compose`、`kyouhanpm-run`→`きょうはnpm-run`、`kyouhae-mail`→`きょうはe-mail` と、守る側の `kyouhara-men`→`きょうはらーめん`・`kyouhako-hi-`→`きょうはこーひー` (どちらも今は ok。`--repro`、2026-10-30) を足して赤を確かめ、直したあと broken 0・追加行が全部 ok。判定ロジックを変えるので、査読員が境界例 (`kyouha` + 長音を含む外来語のローマ字 数百語) を作って base と比べる。
   - scope: core

2. **子音だけの英語片 + `-` が長音になる (`ls-files` → `lsーfiles`、`cd-rom` → `cdーrom`)**
   - 背景: 本家 #1349 の単独の形。本家は v1.4.1-pre.1 で単独の `pt-query-digest` を直したが、fork は単独でも `ptーquery-digest`・`lsーfiles`・`rmーrf` になる。コマンド名・略語に多い形。
   - minimum 要件: 母音を含まない英字の並び (`ls`・`pt`・`cd`・`rm` など) の直後の `-` に英字が続くときは、`-` を長音にせず英字のまま確定する。
   - 完成条件の案: 正解表に `pt-query-digest`・`ls-files`・`cd-rom`・`rm-rf` (いずれも英字のまま) を足して赤を確かめ、直したあと broken 0・追加行が全部 ok。守る側として、既にある `ra-men` → `らーめん` (正解表) と K09 の行頭 `-` の行が変わらないことを確かめる (`n-to` は今 `ん-と` で、長音を守る例にはならない。`--repro`、2026-10-30)。本家の直し方 (PR #1345 か v1.4.1-pre.1 の変更) を Mac 側で読んで、写せるか比べる (本家 GPL なのでライセンスは問題ない見込み)。
   - scope: core (候補 1 と同じ所を触る可能性が高い。1 つの要件にまとめるかは人が決める)
