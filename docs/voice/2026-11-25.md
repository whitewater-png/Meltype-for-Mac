## 要件定義書の候補
既存の要件 (main の 001〜042)、10-24〜11-24 の文書の候補、`eval/cases/` (`dai1dan`・`keihaitowagon`・`101kenijouattara` の行は無い)、`tools/check-release.py` と突き合わせた。

1. **リリースの検査で、cask の `input_method` のパスが配布 ZIP の中にあるかを確かめる** (本家 #2373 と同じ型の予防) — scope: swift (Mac の配布の道具 `tools/check-release.py`。core・dictionary ではない)
   - 背景: 本家は cask が ZIP に無いアプリを指して `brew upgrade` が失敗し、版の記録が食い違った。fork の cask は今は正しいが、`check-release.py` は version と sha256 しか見ないので、ZIP の中の並びを変えたときに同じ失敗を出しても気づけない。
   - minimum 要件: `check-release.py` の cask の節で、cask の `input_method` (と、足されたら `app`) のパスが `mac/dist/Meltype-mac-<版>.zip` の中にあるかを確かめ、無ければ失敗にする。
   - 完成条件の案: 正しい ZIP で通り、パスを書き換えた cask・中身を変えた ZIP で失敗する Python のテストを足す (Linux で動く部分はクラウドで、`check-release.py` 全体は Mac で流す)。cask と配布物そのものは変えない。

2. **本家 11-24〜25 の誤判定の 3 形 (`dai1dan`・`keihaitowagon`・`101kenijouattara`。fork では英字に割れない) を正解表とテストで守る** — scope: core
   - 背景: 本家では `dai1dan` が `だi1dan` に割れ、main でも再現する (bot)。fork はかなのままだが、数字を挟んだ形 (`第1弾` 型) の行が正解表に無く、判定を変えたときに崩れても気づけない。要件 019〜025・041 と同じ「本家の報告を守る」型。
   - minimum 要件: `dai1dan`・`dai3dan`・`keihaitowagon`・`101kenijouattara` の今の形 (英字に割れない) を正解表に足す。漢字の形は偽の変換エンジンでは測れないので、判定 (英字か かなか) だけを守る。
   - 完成条件の案: 正解表に上の形を足し、base でも当たる (守るための行なので赤は無い。`--repro` の結果と一致することを確かめる)。Core 全件通過、eval-compare の broken 0。

3. **変換中に ⌘S を押す・別のウィンドウへ移るときに、未確定の文字が消えないことを Mac 実機のチェックリストに足す** (本家 #2339・#2340。Windows の Tk で消える) — scope: swift (コードは変えない。確かめるだけ)
   - 背景: fork はコードの上では、Command つきのキーと入力欄を離れるときに確定してから通す。ただ Tk (Python の IDLE)・ターミナル・Electron など IMK の扱いが癖のあるアプリで実際に残るかは、記録が無い。K95 (Premiere) のように、暗黙の確定が学習に残らない形は既に分かっている。
   - minimum 要件: TextEdit・Safari・ターミナル・IDLE (Tk) で、変換中に ⌘S・⌘Tab・別のウィンドウのクリックをして、未確定の文字が確定されて残るかを確かめる手順と結果を `docs/` の実機チェックリストに足す。消えるアプリがあれば `docs/KNOWN_LIMITS.md` に 1 行足し、直すかは人が決める (直すなら Swift・IMK の入力経路の変更になるので止める条件に当たる)。
   - 完成条件の案: 4 アプリ × 3 操作の結果が実機で埋まる (クラウドでは埋められないので、人に渡すチェックリストになる)。
