## 要件定義書の候補
既存の要件 001〜008 (009〜012 は PR #14〜#17)、10-24〜11-08 の文書の候補と突き合わせた。`[[`・`Obsidian`・`==`・`Metal`・`GPU` (`iGPU` 以外) は過去の文書で `grep` して該当なし。Markdown の記号の全角は 11-05 の文書に本家 #1301 として載せたが、候補にはしていない (本家で進行中のため)。候補 1 はその一部 (`[[`) を、本家の進み方と別に切り出したもの。

1. **Obsidian のウィキリンク `[[…]]` と `==…==`・`%%…%%` が全角になる・前後で揃わない** — scope: core
   - 背景: 本家 #1676 (Obsidian・Discord)。fork でも `[[link]]` → `「「link」」`、`==marker==` → `＝＝marker==`。メモアプリで毎回打ち直すことになる。
   - minimum 要件: `[[` で始まり `]]` で閉じる形は半角の `[[…]]` で確定し、中身は今の判定どおり (`[[nikki]]` → `[[にっき]]` か `[[nikki]]` かは人が決める)。`==`・`%%` は前後を同じ幅に揃える。1 つの `[` (`[kyouha` → `「きょうは`) の今の値は変えない。
   - 完成条件の案: 正解表に `[[link]]`・`kyouha[[nikki]]`・`==marker==` と守る行 (`[kyouha` → `「きょうは`、`kyouha]` → `きょうは」`、`2==2` → `2＝＝2` の今の値) を足し、実装前は外れ・実装後は当たる。Core 全件通過、eval-compare の broken 0。記号の幅の判定に触るので、査読員が境界例 (`[[`・`]]` だけ、`[[]]`、`a[[b`、`「「` を打ちたい人の打ち方) を作って base と比べる。本家 #1301 の直し方が出たら合わせるかも人が決める。

2. **Mac の Zenzai を GPU (Metal) で動かし、長い文の変換を速くする** — scope: swift
   - 背景: 本家 #1663 (macOS 27.2・M3 で作者が計測、CPU 5.46 秒 → GPU 2.16 秒)。fork も `ZenzaiCPU` だけで、同じ落ち方を `mac/Package.swift` のコメントに残している。
   - minimum 要件: `mac/build.sh` で実行ファイルに記録する SDK 版を直し、`Zenzai` (Metal) の trait で入力サーバーが落ちずに変換できる。変換結果は CPU 版と同じ。Metal が使えない環境では今の CPU 版か Zenzai なしに戻る。
   - 完成条件の案: Mac で `--self-test` (または `Bench.swift` の速度計測) が通り、長文・短文の変換結果が CPU 版と一致し、時間が短くなる。`tools/check-mac-aot-settings.py`・`tools/check-release.py` が通る。**Swift・ビルド設定の変更で、クラウドでは測れないので CLAUDE.md §5 (実機でしか確かめられない) に当たる。** 人が Mac で進めるか決める。SDK 版を記録し直すと macOS の他の動きも変わる懸念 (本家の記述) を、実機チェックリストに入れる。
