## 要件定義書の候補
既存の要件 001〜014、10-24〜11-12 の文書の候補、`docs/KNOWN_LIMITS.md` と突き合わせた。`re-toga`・`birudoha`・`#1807` は過去の文書で `grep` して該当なし。要件 004 (母音の無い英字 + ハイフン) はハイフンの「後ろ」ではなく「前」の話で、候補 1 とは重ならない。候補 2 は 10-25 の候補 2 (`mac` の候補に `Mac` を出す) と近いが、あちらは候補の一覧に出す話、こちらは確定の形を変える話。

1. **`re-toga` (レートが) が英字のまま残る** — scope: core (`toga` を一覧から外すだけなら dictionary だが、`toga` は英単語なので core 寄り)
   - 背景: 本家 #1841。長音の `-` を含むかなの語の後ろに `ga` が付き、残りの部分 (`toga`) がたまたま英単語のときに丸ごと英字になると推測。`re-towo`・`re-tode` は崩れない。
   - minimum 要件: `re-toga` → `れーとが`。`-` の前が子音 + 母音のかな (`re`) で、`-` を長音として読むとかなの語として成立するときは、後ろが英単語でもかなを優先する。`re-enter`・`re-run`・`co-op`・`e-mail` は英字のまま。
   - 完成条件の案: 正解表に `re-toga` (`れーとが`)・`saisinnokawasere-toga` と守る行 (`re-enter`・`re-run`・`co-op`・`e-mail`・`re-to` → `れーと`) を足し、実装前は外れ・実装後は当たる。Core 全件通過、eval-compare の broken 0。判定ロジックを変えるので、査読員が「かな + `-` + 英単語」の境界例 (`re-door`・`pe-pa`・`se-ten`・`ko-man`・`me-ru`) を自分で作って base と比べる (CLAUDE.md §4)。

2. **`propernouns.txt` に登録した語を、全部小文字で打ったら登録した形 (`GitHub`) で確定する** — scope: core (設定を足すなら swift も)
   - 背景: 本家 #1807 (機能提案)。今は `github` と打つと `github` のまま確定し、`GitHub` にするには候補の一覧を開くか Shift で打つ。10-25 のブログの `mac` → `Mac` の声とも近い。
   - minimum 要件: 全部小文字で打った語が `propernouns.txt` (同梱・利用者のどちらか、どこまで含めるかは人が決める) にあり、英字で確定するときは、登録した大文字小文字の形で確定する。大文字を 1 文字でも含めて打ったら打ったまま。
   - 完成条件の案: Core のテストに「`github` + Enter → `GitHub`」「`kyouhagithubnipushshita` → `今日はGitHubにpushした`」「`GITHUB` → `GITHUB`」を足して赤 → 緑。既定を変えるか設定にするかは人が決める (既定を変えると正解表の多くの行の期待が変わるので、eval-compare の broken の扱いを先に決める)。Mac 実機での確定の形は**未確認**。

3. **変換ボックスの表示と確定の結果がずれる形をまとめて直す (`birudoha`・`obsidianwo`・`altwoosu`)** — scope: core
   - 背景: 本家 #1814。`birudoha` は表示が `びるdoha` なのに Enter で `びるどは` になる。11-10 (`altwoosu`)・11-12 (`obsidianwo` は表示 `obsidianを`・確定 `おんしぢあんを`、`obs` は表示 `おbs`・確定 `おば`) と合わせて 3 件目で、向きは両方ある。11-12 の候補 1 は「ずれを別の要件にするかは人が決める」としていた。
   - minimum 要件: Enter で確定した文字は、確定の直前に変換ボックスに出ていた文字 (英字の部分は英字、かなの部分はかな) と同じになる。どちらに合わせるか (表示を直すか確定を直すか) は語ごとではなく 1 つの決まりで決める。
   - 完成条件の案: Core のテストに `birudoha`・`obsidianwo`・`obs`・`altwoosu` で「`--repro` の `showing` と `committed` が一致する」を足して赤 → 緑。正解表の全行でも `showing` と `committed` が食い違う行を数えて 0 にする (今の件数は数えていない)。Core 全件通過、eval-compare の broken 0。実機の変換ボックスの表示は**未確認**。
