## 要件定義書の候補
既存の要件 (001 done、002〜004 approved で PR 済み) と、前回までの候補 (`docs/voice/2026-10-24`〜`10-30`) とは重ならないことを確かめた。

1. **`beep` がかなに崩れる (`beepon` → `べえぽん`、`beep` → `べえp`)** — scope: dictionary
   - 背景: 本家 #1377 (Mac、再現済み)。fork でも `--repro beepon` → `べえぽん`、`beep sound` → `べえpsound` (2026-10-31 クラウド)。要件 002 (`ost`) と同じ「辞書に無い短い英単語がローマ字として読める」形。
   - minimum 要件: `beep` と、`beep` の後ろに英単語・助詞が続く形が英字のまま残り、日本語の `beepon` 以外の `be`・`bee` 始まりの語 (`beeru`・`bee` など) は変わらない。
   - 完成条件の案: 正解表 `eval/cases/short-words-in-english.tsv` に `beep`・`beep sound`・`beep ga naru` と守る行を足し、実装前は外れ・実装後は当たる。eval-compare の broken 0、Core 全件通過。`beepon` → `beep音` は漢字なので Core では `beepおん` までしか測れない (期待の形は要件で決める)。

2. **Mac で未確定中の前方 Delete・Clear・専用操作の無い F キーを、操作キーとして扱う** — scope: swift
   - 背景: 本家 #1375 (Mac、US 配列、毎回)。fork は私用領域の文字を渡さない手当てが既にあるが、Clear・F3 などが「その他の文字キー」として本体に渡ったときの振る舞いと、Apple ロゴ (U+F8FF) まで落ちるかは未確認。
   - minimum 要件: 未確定中に前方 Delete・Clear・F1〜F5・F11〜F20 を押しても未確定に文字が足されず、専用の操作が無いキーは確定してアプリへ渡る。F6〜F10・矢印・Page Up/Down の既存の操作と、Option+Shift+K の Apple ロゴ・絵文字の入力は変わらない。
   - 完成条件の案: Core 側で測れる部分 (仮想キー 0x07・文字 0 が来たときの振る舞い) をテストに足し、残りは実機チェックリスト (テキストエディット・US 配列で上のキーを 1 つずつ)。**IMK の入力経路 (`InputController.swift`・`KeyMapping.swift`) に及ぶので `CLAUDE.md` §5 の止める条件に当たる。人が実機で確かめる前提の要件。**
