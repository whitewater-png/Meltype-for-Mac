## 要件定義書の候補
既存の要件 001〜014 (と PR #20 の 016・#23 の 018・#24 の 019・#25 の 020)、10-24〜11-18 の文書の候補 (11-02・11-10 の本家 #1711「英字断片 + かな」を含む)、`eval/cases/` と突き合わせた。

1. **小文字・記号入りの固有名詞の語尾を、かなにせず英字のまま残す** (本家 #2037) — scope: core (または dictionary)
   - 背景: `pazolite` → `ぱぞlite`、`oeksound` → `おえksound`、`u-he` → `うーへ`、`YUC'e` → `YUC’え` と、英字とかなが混ざった形や、英字の名前がかなになる形が fork でも起きる (大文字で始まる `Omnisphere` などは起きない)。
   - minimum 要件: 単独で打った `pazolite`・`t+pazolite`・`oeksound` は英字のまま入る。`u-he`・`YUC'e` は、判定で直すか辞書に入れるか、そもそも直すべきか (`うーへ` を期待する人もいる) を人が決める。`pazo`・`kyouhapazo` などのかなの形は変えない。
   - 完成条件の案: 正解表に上の形を外れる行として、`pazo`・`oeksoundnoplugin`・`kyouhapazolitewokiku` (どう出すべきかは人が決める) を守る行として足し、直す前は外れ・直した後は当たる。Core 全件通過、eval-compare の broken 0。辞書で直すなら 016・014 と同じ流儀、判定で直すなら査読員が「英字断片 + かな」の境界例 (本家 #1711 の `supika`・`onvif` など) を作って base と比べる。

2. **本家 11-19 の誤判定のうち、fork で起きないものを正解表に守る行として足す** — scope: core (正解表とテストだけ。判定ロジックは変えない)
   - 背景: 本家 #2037 の大文字で始まる 7 語 (`Omnisphere`・`Spectrasonics`・`Kilohearts`・`KiloheartsEssentials`・`ShaperBox`・`Melodyne`・`Tsundere`)、#2038 の `guranyura-`・`ROMpura-`・`konpi`・`konpiwo`、#2065 の `sasetaken`、#2062 の `Genshin` は fork では今起きないが、正解表に同じ形の行が無い。019・020 と同じ考え。
   - minimum 要件: 上の形を、今の出力 (英字のまま / `ぐらにゅらー`・`ROMぷらー`・`こんぴ`・`こんぴを`・`させたけん`) で `eval/cases/` に足す。020 に足すか新しい要件にするかは人が決める。
   - 完成条件の案: 足した行が今の main で当たる。わざと崩した版で外れることを一度確かめる。Core 全件通過、eval-compare の broken 0。

3. **確定前の文が一度に別の形に変わったとき、直前の形に戻せるか確かめる** (本家 #2064) — scope: swift
   - 背景: 本家で、長い未確定の文の末尾の `?` のあと文全体がローマ字の表示になり、戻せず、Esc で全部消えたという報告。fork の Mac 版で同じことが起きるかは分からない。
   - minimum 要件: まず実機で、長い文 + `?`、その後 Backspace・Esc を打って、表示が戻るか・消えるかを確かめる (人の作業)。起きるなら、Core で `?` の前後の判定を正解表に足す。
   - 完成条件の案: 実機チェックリスト (TextEdit・Safari で、長い文 + `?` → Backspace で元の表示に戻る) を人が埋める。Core 側で再現する形が見つかれば、その形を正解表に足して直す。入力経路 (Swift) に触るなら CLAUDE.md §5 で止めて相談する。
