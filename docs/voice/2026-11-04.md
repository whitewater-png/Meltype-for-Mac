## 要件定義書の候補
既存の要件 001〜004、PR #10 (005)・#11 (006)・#12 (007)、10-24〜11-03 の文書の候補とは重ならないことを確かめた (`icloud`・`itunes`・`sin`・`cos`・`tan` を過去の文書・`eval/cases/`・`docs/requirements/` で `grep`、該当なし)。

1. **`iCloud`・`iTunes` の頭の `i` がかなになる (`いCloud`)** — scope: core
   - 背景: 本家 #1530。fork の Core でも `iCloud` → `いCloud`、`iTunes` → `いTunes`。`iPhone`・`iPad` は崩れないので、語ごとに結果がばらつく。
   - minimum 要件: 小文字の `i` の直後に大文字で始まる英字が続く形 (`iCloud`・`iTunes`) で、`i` をかなにしない。`ichi`・`ikou`・`iCloudnihozon` の今の値は変えない。
   - 完成条件の案: 正解表に `iCloud`・`iTunes` と守る行 (`ichi`・`ikou`・`iPhone`・小文字だけの `icloud` をどうするかは人が決める) を足し、実装前は外れ・実装後は当たる。Core 全件通過、eval-compare の broken 0。判定を変えるなら、`i` で始まる日本語への回帰を査読員が境界例を作って base と比べる。

2. **`sin60`・`tan45`・`cos30` が `しん60`・`たん45`・`こs30` になる (三角関数 + 数字)** — scope: core
   - 背景: 本家 #1519 (数式を Gemini・GitHub に打つ)。fork でも同じで、`cos30` は英字とかなが混ざる。`log10` は英字のまま。
   - minimum 要件: `sin`・`cos`・`tan` の直後に数字が続く形 (`sin60`・`cos30`・`tan45`) を英字のまま残す。`sin` 単独・`tan` 単独 (`しん`・`たん` と読みたい場合がある) と、後ろに日本語が続く形の今の値は、査読員が `--repro` で取ってから守るか決める。
   - 完成条件の案: 正解表に 3 語と守る行を足し、実装前は外れ・実装後は当たる。Core 全件通過、eval-compare の broken 0。数字が続く形の判定に触るので、`ni2` のようなかな + 数字の打ち方への回帰を査読員が確かめる。

3. **覚えた英単語が日本語の途中に割り込む (`konotennmo` → `こnoteんも`) を Core のテストで確かめる** — scope: core
   - 背景: 本家 #1512 (Windows)。F10 で `note` を英語として覚えさせると、`この点も` と打ちたい途中に `note` が入る。fork に同じ学習の仕組みがあるかと、学習後に起きるかはまだ見ていない。
   - minimum 要件: まず fork の Core で「`note` を学習させたあと `konotennmo`」を再現するテストを書き、起きるかを確かめる。起きるなら、覚えた語は語の途中 (前後が小文字のローマ字) では割り込ませない。単独で打った `note` は英字のまま。
   - 完成条件の案: Core のテストに学習後の `konotennmo` → `このてんも` と単独の `note` → `note` を足し、実装前の結果を記録する (起きなければ「起きない」を守るテストとして残して終える)。Core 全件通過、eval-compare の broken 0。学習データのファイル形式を変えるなら止める (`CLAUDE.md` §5)。
