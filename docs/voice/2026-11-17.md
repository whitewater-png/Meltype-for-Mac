## 要件定義書の候補
既存の要件 001〜014 (と PR #20 の 016・PR #23 の 018)、10-24〜11-16 の文書の候補、`docs/KNOWN_LIMITS.md` (K25・K79)、`docs/USAGE.md` と突き合わせた。

1. **日本語の文の中で、数字の後の `,` で確定したら読点にする** (本家 #1989) — scope: core
   - 背景: `kosuuha100,` を Enter・Space で確定すると `こすうは100,` と半角の `,` が残る。今は「次に数字以外を打ったら読点」の規則なので、`,` が最後のときに読点にならない。
   - minimum 要件: 数字の前が日本語 (かな・漢字) のときは、最後の `,` を確定で `、` にする。英文の中 (`100, 200`)・桁区切り (`1,000えん`)・数字だけ (`100,`) は今のまま。数字だけのときの扱いは人が決める (本家は `100、` を期待)。
   - 完成条件の案: 正解表に `kosuuha100,`→`こすうは100、` を外れる行として、`100, 200`・`1,000えん`・`100、です` を守る行として足し、直す前は 1 行だけ外れ・直した後は全部当たる。Core 全件通過、eval-compare の broken 0。数字の後ろの判定に触るので、査読員が境界例 (`ver1.2,`・`2026,`・英文の中の `in 2026,`) を作って base と比べる。

2. **本家 11-17 の誤判定のうち、fork で起きないものを正解表に守る行として足す** — scope: core (正解表とテストだけ。判定ロジックは変えない)
   - 背景: 本家 #1984・#1985・#1987・#1990・#1991 の形 (`baguhoukoku`・`tunagarumademattekara`・`CLAUDE.mdwohiraku`・`,nisuruwo`・`reibunn:pregnant_man:`) は fork では今起きないが、正解表に同じ形の行が無いので、後の本家追従で崩れても回帰ゲートで気付けない (前回の候補 3 → 018 と同じ考え)。
