## 要件定義書の候補
既存の要件 001〜004、PR #10 (005 `beep`)・#11 (006 `^`)、10-24〜11-01 の文書の候補とは重ならないことを確かめた (番号・語句を過去の文書で `grep`)。11-01 の候補「Homebrew で入れた直後にログアウトせず使えるようにする」とは近いが、そちらは**初めて入れたとき**、下の 1 は**入れ替え (upgrade) のとき**の話。

1. **`brew upgrade` (Meltype.app の入れ替え) の後も入力メニューに残るようにする** — scope: swift (と `mac/install.sh`・Homebrew の cask)
   - 背景: 本家 #1433 で、入れ替えのたびに入力メニューから消え、システム設定で追加し直すしかないという報告 (本家の作者が優先: 高)。fork も同じ登録の作りで、起きるかは未確認。
   - minimum 要件: Meltype for Mac を入れた状態で upgrade (または `install.sh` での入れ替え) をした後、システム設定を開かずに入力メニューで選んで打てる。初めて入れるとき・uninstall の結果は変えない。
   - 完成条件の案: 先に Mac 実機で「入れ替え → 入力メニューから消えるか」を確かめて、起きるときだけ進める。チェックリスト (upgrade・reinstall・`install.sh` の入れ替えの後に、入力メニューに残り、TextEdit で打てる) を人が実機で回す。**インストールの経路に触れ、実機でしか確かめられないので `CLAUDE.md` §5 に当たる。**

2. **`/` を打ってスペースを押したら、`・` などの記号の候補を出す** — scope: core
   - 背景: 本家 #1446 (Mac、Slack)。ふつうの IME では `/` + 変換で `・` が出るが、Meltype では候補が出ず `/` のまま確定する。fork の仕様は「`/` だけなら半角、`・` は `z/`」で、知らない人には `・` の出し方が分からない。
   - minimum 要件: 変換ボックスが `/` だけのときにスペースを押すと、`・`・`／`・`/` が候補に出る (並び順は人が決める)。Enter・打ち続けたときの今の動き (`/` のまま・`docs/hello` のようなパスは英字のまま) は変えない。
   - 完成条件の案: Core のテストに「`/` + スペースで候補に `・` が入る」と、守る例 (`/` + Enter → `/`、`a/b`・`~/docs` の今の値) を足し、実装前は赤・実装後は緑。Core 全件通過、eval-compare の broken 0。候補の窓の見え方は実機チェックリスト (Slack・TextEdit)。

3. **月配列で打てるようにする** — scope: core (設定画面に項目を足すなら swift)
   - 背景: 本家 #1415 の提案。本家の作者は X で対応の PR を出すつもりと書いている。fork はローマ字入力と JIS かな入力だけ。
   - minimum 要件: 設定で月配列 (版は人が決める。本家の対応を待って揃えるのも手) を選ぶと、キーの対応表どおりのかなが変換ボックスに入り、そこから先 (変換・英語の自動判定) はかな入力と同じに動く。ローマ字入力・JIS かな入力の今の動きは変えない。
   - 完成条件の案: Core のテストに、配列の対応表の全キーと、前置シフト (月配列の 2 打で 1 字) の例を足して実装前は赤・実装後は緑。Core 全件通過。**本家が先に入れるなら、取り込みで済むかを先に見る。** 設定の形式に触れるなら `CLAUDE.md` §5 に当たる。
