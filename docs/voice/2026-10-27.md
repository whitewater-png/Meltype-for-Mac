## 要件定義書の候補 (3 件まで)
既存の要件は 001 (done) と 002 (PR #7、`ost`) で、どれも重ならない。

1. **入力ソースが入力メニューやシステム設定に重複して並ぶ**
   - 背景: note の Mac 利用記で、再起動後に入力ソースの Meltype が 15 個・入力メニューに 2 個並んだ (本家は PR #522 で整理)。
   - minimum: fork で再起動後に重複が出るか実機で確かめ、出るなら Meltype を 1 組だけ残す。
   - 完成条件の案: 実機チェックリスト (インストール → 再起動 → システム設定の入力ソースと入力メニューで Meltype が 1 組。`defaults read com.apple.inputsources` と `com.apple.HIToolbox` の両方に 1 件ずつまで)。Core では測れない。
   - scope: swift (登録の処理。`CLAUDE.md` §5 により人の判断を仰ぐ)
2. **変換中の Home・End・Page Up・Page Down の振る舞いを決めて守る**
   - 背景: 本家 #1244 で、変換中の Fn+矢印で私用領域の文字が入る。fork は文字を渡さないが、Core に Home・End の扱いが無く、どう動くかは未確認。
   - minimum: 変換中に Home・End・Page Up・Page Down を押しても変換ボックスに文字が増えない。動き (確定してから移動、など) を 1 つに決める。
   - 完成条件の案: Core のテスト (変換中に仮想キー 0x24・0x23・0x21・0x22 を文字 0 で渡し、変換中の文字が増えない) を足して通す。実機チェックリスト (US 配列で `a` → Fn+← などを TextEdit・Safari で)。
   - scope: core (振る舞いを決める) + swift (キーの渡し方。人の判断を仰ぐ)
3. **長文を確定せずに打ち続けたとき英字のまま残る場合があるかの切り分け**
   - 背景: note の Mac 利用記の報告。fork の Core では 292 文字まで再現しない。
   - minimum: 300 文字を超える入力を Core で測る手段を用意し、Core の問題か、azooKey・実機の側かを切り分ける。
   - 完成条件の案: 400 文字程度のローマ字文が全部かなで確定する Core のテストを足す (通れば守りとして残す)。外れれば別の要件にする。実機では TextEdit で同じ文を確定せずに打つ。
   - scope: core (切り分け。原因が Swift なら別の要件)
