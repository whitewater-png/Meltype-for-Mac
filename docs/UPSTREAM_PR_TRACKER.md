# 本家 PR の取り込み管理表

[UPSTREAM_PR_SURVEY.md](UPSTREAM_PR_SURVEY.md) (2026-10-11 の調査結果) をもとに、**どの本家 PR を、どの項目で、どこまで取り込んだか**を管理する。
項目の中身 (現象・原因・修正・数字・トレードオフ) は [IMPROVEMENT_PLAN.md](IMPROVEMENT_PLAN.md) の各 P 番号の節に書く。この表は進み具合だけを持つ。

## 進め方 (1 項目ごと)

1. 別のコピーの上で実装する。先にテストを足して、修正前に赤になることを確かめる (赤→緑)。
2. 変更前と変更後を、実機の判定器 (`NSSpellChecker`) と同梱の単語表 (`BuiltInWordChecker`) の**両方**で比べる。`--repro` は実機と違う答えを出すことがある。
3. 変えていないはずの入力 (日本語の語 + 助詞、実在の英語、自作の入力) を数千件まわし、差分を全件見る。
4. 実装した人とは別のエージェントが査読する。指摘がなくなってからリポジトリに入れる。
5. 全テストが通ることを確かめて、1 項目 1 コミットで入れる (**push はしない**。タグ・公開はリョウさんの許可が要る)。
6. `IMPROVEMENT_PLAN.md` に P 番号の節を追記し、この表の状態を更新する。
7. 実機で確かめる点は「実機確認待ち」として残し、確かめたら日付と結果を書く。

状態の言葉 (実機確認待ち = コミット済みで、実機での確認が残っている): 未着手 / 作業中 / 査読中 / コミット済み / 実機確認待ち / 完了 (実機確認済み) / 保留 / 見送り / 対象外 / 済 (すでに同等)
