## 2. issue の要求

### #979（Windows 起票・共通）
- `ry`=らい / `ryp`=りょう / `ngh`=にゅう のような TSV テーブル。
- **行順ではなく最長一致**。`ry` の時点では らい を表示しつつ後続を待ち、`p` で りょう に置き換える。
- 後続がどの定義にも一致しなければ、短い定義の結果を維持し、後続キーはそのまま残す（`ryt` → `らいt`）。

### #1021（AZIK）
- 定義 **317 件**（英字）＋ **非英字 5 キー**（`;`=っ、`-`/`:`=ー、`[`=「、`]`=」）。
- 最大キー長 **3**（`kya`/`kga`/`ngh`/`wso`/`tgi` など）。出力が複数かなの定義 **243 件**。
- **重複キーあり**（`fu`/`wo`/`kn`/`sn`/`nn`/`mn` など）→ 後勝ちかエラーの規則が必要。
- **「短い定義が長い定義の接頭辞」の組は 0**。つまり AZIK は「外部テーブル＋固定ルールよりテーブル優先＋非英字キー」だけで動く可能性が高い。**#979 の保留機構は AZIK には必須ではない**（#979 には必須）。
- 固定ルールとの衝突: `nk`=にん / `nz`=なん は「n+子音→ん」と、`kk`=きん は「同じ子音の連続→っ」と正面衝突。これらはテーブル lookup より**前**に走るため、テーブルを足すだけでは AZIK が勝てない。
- 非英字キーは `AnalyzeCore` の英字チェック（184-185 行）で拒否され、`CompositionText.Append`（72 行）では `Symbol()`（271 行）が先に全角化する。**テーブル照会を `Symbol()` より前に置く必要**。

## 3. 設計案

### ファイル形式
- **TSV 1 行 1 定義**: `<キー列>\t<かな>`。`#` コメント・空行無視。キーは小文字化。出力はひらがな・記号可。
- 重複キーは既定「後勝ち」＋起動時にログ警告。
- 同梱: `dictionaries/romaji.txt`（標準の TSV 化）、`dictionaries/romaji-azik.txt`。ユーザー上書きはデータフォルダーの `dictionaries/romaji.txt`（`DictionarySource.Load` 型で埋め込みに追記）。
- `dictionaries/*.txt` は `Meltype.Core.csproj:22` のワイルドカードで自動埋め込み、`Backup.cs` の対象にも自動で入る。

### 最長一致アルゴリズム
- `RomajiTable` クラスを新設: `Dictionary<string,string>`＋`HashSet<string> Partials`＋`int MaxKeyLength`＋逆引き。
- 解析は現行と同じ「位置 i で MaxKeyLength から 1 まで降順」。**MaxKeyLength はテーブルから動的に算出**（4 固定をやめる）。
- カスタム時は **テーブル → ん/っ固定ルール → Partial** の順（標準時は従来順で回帰なし）。
- 非英字キーは「テーブルに定義がある文字は許可」に変更し、`Append` では `Symbol()` の前に照会。

### #979 の保留機構
- `Normalize` で「最後のトークンがより長いキーの接頭辞で、`final` でないなら `_units` に確定せず `_pending` に残す」。次のキーで伸びれば長い定義で 1 単位に確定。
- `final`（Space/Enter/記号/確定）では従来どおり短い定義で確定 → `ryt` は `らいt`。
- 再結合の可否は仕様判断（推奨は許す）。

### 設定
- `RomajiTableStyle { Standard, Azik, Custom }`（既定 Standard）を `Settings.cs` に追加し、`MacSettingsCatalog.cs` の「入力」に `Choice` で 1 件。
- カスタムは `dictionaries/romaji.txt` 固定（Mac の設定 UI に文字入力欄が無いため）。
- `InputStyle` は変えない（かな入力・自動切替の意味が変わるため）。
- テーブルファイルの再読み込みは mtime 監視（500ms 間隔）＋キャッシュ無効化。

## 5. 主なリスク

- **R1（最高）英語判定との衝突**: AZIK の 2 文字短縮（`st`=した、`kt`=こと、`mn`=もの、`ds`=です、`km`=かも、`ms`=ます…）は英単語・略語・単位と衝突。Meltype の中核「ローマ字のまま英語と日本語を打ち分ける」と正面衝突。**AZIK は日本語入力専用にするか、英語優先のまま AZIK を弱めるかの製品判断が必要**。
- **R2（高）非英字キーの順序**: `;` `[` `]` `:` は今 `Symbol()` で全角化され、`Append` の早い段階で記号として確定。迂回すると句読点・かぎかっこ・`z+記号`・`/`→`・` の既存挙動に波及。
- **R3（高）確定タイミングの変更**: `Normalize` の即時確定をやめると、確定・BS・英語判定・セグメント・学習・`Raw` の意味が変わる。既存テストの回帰が広い。
- **R4（中）static 解除の波及**: `AnalyzeCore` が static なのでテーブル注入は大改造。`DictionaryManagement` が別インスタンスを作るため、入力欄と読みの変換結果が食い違う危険。全生成点で同じテーブルを渡すこと。
- **R5（中）逆引きの組合せ爆発**: AZIK は 1 かなに複数綴り＋短縮があるため `SpellingVariants` が増える。既存 `limit: 64` で抑制されるが、打ち間違い補正の候補が変わる。
- **R6（中）本家との共有**: `src/Meltype.Core` は本家 Windows と共通。設定名・既定値・TSV 形式を本家と決めないと二重管理・マージ衝突。
- **R7（小〜中）テーブル再読み込み**: config.json ではないため `ConfigFileWatch` では拾えない。mtime 監視とキャッシュ無効化を別途実装。
