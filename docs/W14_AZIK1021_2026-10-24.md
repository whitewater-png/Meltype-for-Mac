# W14-2 — 本家 #1021 (AZIK): カスタムローマ字表の非英字キーと英語判定の衝突

2026-10-24。#1021 は「ローマ字テーブルに AZIK を使っているので、変形ローマ字に対応してほしい」という提案。W11-1 / W13-1 で入れたカスタムローマ字表 (#979) を AZIK の定義が書ける状態にする「仕組み」の部分を実装した。**AZIK の定義データは同梱していない。push 前・実機未確認。**

## 1. 実装範囲

| 項目 | 内容 |
| --- | --- |
| A4 非英字キー | 表のキーに `;` `:` `[` `]` `@` `-` `,` `.` `/` `'` `^` `\` を使える (`RomajiTable.SymbolKeyChars`)。数字・括弧・引用符・`! ? ~ #` は不可 (行ごと無視 + 警告) |
| 記号の優先 | `CompositionText.Append` の先頭で、表 ON・記号入りのキーあり・`pending + 記号` が表のキー (または長いキーの先頭) のときだけ pending に入れて、既存の B1/B2 (保留・長短キー・確定・BackSpace) に乗せる |
| 不一致 | `pending + 記号` がキーに届かなくても、記号単独がキー (の先頭) なら、今の pending を標準の綴りで確定してから記号を新しいキーの先頭にする。どちらでもなければ従来の記号の規則に戻る |
| z + 記号 | pending が `z` で `ZSymbol(c)` がある記号 (`z.` `z[` など) は、`z` + 記号がキーでない限り従来の規則が先 |
| 途中で確定 | キーの途中の記号は従来の `Symbol()` (`[` → 「、`;` → `;`)、英字は標準の綴りで確定 (`PartialRestUnits`。Normalize と `PendingText(final)` で共通) |
| C1 英語判定 | `CompositionDetector.IsTableOnlySpelling`: 区間全体が「標準の綴りで読めず、表のキーを使うと最後まで読める小文字の綴り」で、英単語として知られていなければ日本語。`IsEnglishSpan` と、`Segment` の「辞書にない英単語を最初から打っているなら全体を英語」の 2 か所で使う |
| サンプル表 | `docs/samples/romaji-sample.tsv` (8 行、自作、AZIK ではない) |
| 文書 | `docs/CUSTOM_ROMAJI.md` を新設。Mac 設定画面と `Settings` の説明文に非英字キー対応を追記 |

差分の場所: `RomajiTable.cs` (Parse・`HasSymbolKeys`・`Extends`)、`RomajiDetector.cs` (`AnalyzeCore` の英字チェック 1 行)、`CompositionText.cs` (hook と確定の補助)、`CompositionDetector.cs` (C1)。

## 2. C1 の規則 (どこまで日本語にするか)

| 入力 (サンプル表: `st`=した `kt`=こと) | 結果 | 理由 |
| --- | --- | --- |
| `stkt` | したこと | 標準で読めず、表で全部読める、英単語ではない |
| `kyouhastkt` | きょうはしたこと | 同上 (文中) |
| `string` `ring` `apple` `stop` `test` `stay` `last` `must` | 英字のまま (OFF と同じ) | 表で最後まで読めない (`ng` `p` など余る)、または表のキーを使わない |
| `stereo` (`st`+`e`+`re`+`o`) | 英字のまま | 最後まで読めるが英単語として知られている |
| `stkta` など、表のキーで始まるだけで最後まで読めない語 | 変えない | 英語判定は従来どおり |

「表のキーが語全体を覆うとき」だけ日本語にし、「表のキーで始まるだけ」「標準で読める」「英単語」は触らない、という狭い規則にした。表 OFF・表なしは `IsTableOnlySpelling` が false なので従来と同じ。

## 3. 表 ON 時の英語判定への影響 (測定)

`AzikSymbolKeyTests.Measure_EvalCases_SampleTableOnVsOff_NoDiffWithoutKeys`: eval/cases の全 648 件 (ASCII だけの打鍵) を、サンプル表 ON / OFF で同じ Keyboard に打って、確定結果と表示を比べた。

- 表のキー (`;` `:` `k;` `s;` `@` `[` `st` `kt`) を**含まない入力 614 件: 差 0** (テストで固定)。
- 含む 34 件: 差 8 件。**8 件すべて記号キー (`[` `;` `:` `@`) の置き換え**で、英語判定の変化ではない (`[kagi]` → `『かぎ』`、`@yksr_melt` の `@` → ん、`Need to do:` の `:` → ー など)。`st` を含む英文 (`last` `must` など) の差は 0。
- 記号キーを持つ表を ON にすると、メンション `@`・括弧 `[ ]`・文末の `: ;` が表のキーになる。これは表を書いた人の選択で、`CUSTOM_ROMAJI.md` に明記した。

## 4. 赤 → 緑

`AzikSymbolKeyTests` (13 件) を先に書き、`CompositionText` の hook を外した状態 (`RomajiTable` の読み込みと `AnalyzeCore` だけ変更済み) で実行 → **7 件が赤** (`; = っ` が `;` のまま、`k;`・`s;k;`・`ak;` の BackSpace・`ka;`・`;a`・`z;`、設定 ON/OFF の対照、C1 の `stkt`)、6 件が緑 (Parse・サンプル表・OFF 系 2 件・英語の綴り 2 件・測定。守りのテストは最初から緑でよい)。hook と C1 を入れる途中で、`stkt` は `IsEnglishSpan` だけの guard では赤のままだった (`Segment` の「辞書にない英単語を最初から打っているなら全体を英語」が別経路) → 2 か所目の guard で緑。最終は 13/13。

既存の `CustomRomajiTableTests.Parse_IgnoresBadLinesAndKeepsGood` は `;` を「無視される非英字」の例にしていたため、`(` に変えた (`;` が有効になったため。意図した変更)。

## 5. 制限 (正直に)

1. 記号キーの待ち表示: キー待ちの間 (`[` が `[a` の先頭など)、表示は記号そのまま (`[`) で、確定で `「` になる。
2. 記号キーを持つ表では、その記号の既定の働き (メンションの `@`、`:` `;` の英文の区切りなど) が、キーが揃う場面で表に置き換わる。
3. C1 は区間全体が表だけで読めるときに限る。表のキーが英語の語の一部に当たるだけの場合は変えない。ステレオ (`stereo`) のように英単語でもある綴りは英語のまま。
4. `IsTableOnlySpelling` は区間ごとに呼ばれ、標準で読めない区間では表の取得 (更新日時の確認) を伴う。ON のときだけ。体感の遅延は未計測。
5. 変換ボックスだけ。Windows の `CompositionService`・`ScoreEngine.CreateDefault`・辞書管理画面は未配線 (W11 の A2 のまま)。
6. 実際の AZIK の定義 (拗音の拡張、`q` `;` などの組み合わせ) をそのまま入れたときの網羅確認は未実施。仕組み (記号キー・保留・英語判定) を整えただけで、AZIK として使えるかは利用者の表の中身次第。
7. 実機 (Mac の IME) では未確認。キー配列 (JIS / US) で `;` `:` `@` の物理キーが違う点は、表に実際に入力される文字で書く前提。

## 6. ライセンス (AZIK の同梱)

- AZIK の定義 (fcitx5-anthy の `azik.sty` など) は読まず・コピーしていない。Meltype には含めない。
- `THIRD-PARTY-NOTICES.md` への追記は**不要と判断**: 今回、第三者のデータ・コードを一切同梱していない。サンプル表は自作で、AZIK の定義とは無関係な 8 行 (`;` → っ など、仕組みを試すための例)。
- 利用者が自分で AZIK の定義を用意する場合は元のライセンスを確認する旨を `docs/CUSTOM_ROMAJI.md` の冒頭に書いた。同梱 (A5) をする場合は、ライセンス表記と `THIRD-PARTY-NOTICES.md` の追記が別途必要 (W11 の表のまま)。
