## Mac 版に取り込むと効く候補 (2026-10-22 時点の判断)

判定の目安: **採用** = そのまま/小さな変更で入る / **調査** = まず再現と原因を見る / **大型** = 設計から / **済** = すでに同等 / **見送り** = Mac では効かない・方針に合わない。

### 優先して見る候補

| # | 対象 | 内容 | 判定 | 理由 |
| --- | --- | --- | --- | --- |
| 976 | Mac | Spotlight の検索バーで候補が裏に隠れる | **調査 (最優先)** | Mac 固有の不具合。候補ウィンドウの `level` は `host.level + 1` だが、Spotlight の結果ウィンドウは別の高いレベルの可能性がある。まず再現と `NSWindow.Level` の実測から |
| 1073 | 共通 | `config.json` の JSON Schema を書き出す | **採用 (低リスク)** | 設定の書き間違いを起動時に検出できる。Mac の設定タブと二重管理になりがちな `config.json` の安全性が上がる。`JsonSchemaExporter` で `Settings` から生成 |
| 1024 | Mac | Homebrew Cask の SHA-256 不一致が再発 | **調査** | Mac の配布経路そのもの。`tools/update-cask.py` とリリース手順のどこで食い違うかを再現する。利用者の更新を止めるので優先度は高い |
| 1029 | 共通 | Space で英文を途切れさせず、文脈判定と Space 2 回の日本語変換を両立 | **調査** | うちは `SpaceAroundEnglish` の設定があるので、まず今の挙動と issue の期待の差を並べる。Core の判定に手を入れるので回帰ゲート必須 |
| 979 | 共通 | カスタムローマ字テーブルを最長一致で処理 | **大型** | うちの Core にカスタムテーブル自体が無い (grep で 0 件)。テーブルの読み込み・最長一致・テスト基盤から作る必要がある。AZIK (#1021) も同じ基盤の上 |
| 972 | 共通 | 変換中の文の一部だけを削除して打ち直す | **大型** | 利用価値は高いが、文節の選択・削除・再変換の状態機械に手を入れる。設計と実機確認を含めて 1 案件として扱う |
| 990 | 共通 | 日本語の確定直後の `/` を `・` にするオプション | **採用 (小)** | 設定 1 つで済む。既存の「記号を全角にする」と同じグループに置ける |
| 1047 | 共通 | 確定後に前の品詞を見て助詞を自然にする | **見送り (今は)** | 判定エンジンの語彙・品詞の情報が要る。研究寄りで、回帰の影響範囲が読みにくい |
