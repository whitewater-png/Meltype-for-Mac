# 013 [[…]] を半角のまま確定する

## 背景 (誰が、何に困っているか)
- 本家 #1676 (Obsidian): ウィキリンク `[[` が `「「` になり、1 文字ずつ直している。
- 今の挙動 (Core の `--repro`、2026-11-10 クラウド): `[[link]]` → `「「link」」`、`kyouha[[nikki]]` → `きょうは「「にっき」」`、`[[]]` → `「「」」`。
- 日本語の入力では `[` `]` は `「」` (Microsoft IME と同じ。英単語の後ろでも `「」`: bot「Thinking」)。この規則は変えない。

## 今の動き
- `CompositionText.Symbol` が `[` → `「`。半角に戻す `HalfWidthOpeners` は `[ ]` を対象にしていない (`Openers` に無い)。
- 本家の扱いは未確認 (クラウドから届かない)。本家 #1301 (Markdown 記号の全角) は進行中のためそちらには触れない。

## minimum の要件
1. `[[` (2 つ並んだ `[`) と、そのあとに続く `]]` (2 つ並んだ `]`) は、4 つとも半角で確定する。中身は今の判定どおり (`[[nikki]]` → `[[にっき]]`、`[[link]]` → `[[link]]`)。
2. 今の値を変えない: `[` が 1 つ (`[kyouha]` → `「きょうは」`)、閉じない `[[` (`[[kyouha` → `「「きょうは`)、開かない `]]` (`kyouha]]` → `きょうは」」`)。

## 非目標 (今回はやらない)
- `==…==`・`%%…%%`・`**…**` など、前後で幅が揃わない他の記号 (どちらに揃えるかは人の判断。別の要件にする)。
- `![]()` の `！`、`[` 1 つの扱い、本家 #1301 の Markdown 記号全般。
- `[` が 3 つ以上続く形は、閉じにいちばん近い `[[` だけ半角 (`[[[a]]]` → `「[[あ]]」`)。組にならない `]` は全角のまま (`[[a]]]` → `[[あ]]」`)。
- 中に空白のある `[[Hello World]]` は、空白で前半が先に確定するので `「「Hello World」」` のまま (限界)。
- 閉じの前に別の `[[` がある外側の `[[` は組ませない (`[[a[[b]]` → `「「あ[[b]]`)。
- `[[nikki` + Space で先に変換してから `]]` を打つ形は、前半が先に確定するので `「「日記」」` のまま (Core では直せない。限界)。
- 打っている途中の表示: `[[nikki` の間は今までどおり `「「`、`]]` を打った時点で `[[` に変わる (ちらつきは Mac 実機で未確認)。
