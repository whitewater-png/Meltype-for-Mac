# 043 ユーザー辞書の短い語が、エンジンの文節の頭で、別の語の読みの一部だけを覆って割り込む

## 背景 (誰が、何に困っているか)
- 報告: ユーザー辞書に読み「しゅう」で名前 (個人名) を登録していると、`gomiwoshuushuusuru` (ごみをしゅうしゅうする) が「ゴミを<登録語>週する」になる。期待は「ゴミを収集する」。登録した実際の語は、この文書にもコード・テストにも書かない (ここでは しゅう → 秋 の代わりの語で書く)。
- 原因を実物で確かめた (2026-11-26、`MeltypeIME --convert-eval` に文節の区切りを出す一時の変更を入れて。コミットしていない): 実際の azooKey は `ごみをしゅうしゅうする` を、Zenzai OFF でも ON でも `ごみを|しゅうしゅうする` (収集する) の 2 文節に切る。`しゅうしゅうする` は 1 文節なので、先頭の しゅう は**文節の頭**にあたり、要件 032 以前から残る「文節の頭なら短い語も使う」(`starts.Contains(position)`) の条件で登録語が入る。残りの `しゅうする` は 週する になる。同じ形: `しゅうしゅうした`・`しゅうかんする`・`しゅうちゅうする`・`しゅうせいする`・`しゅうりょうする`・`しゅうまつ` (文の先頭も同じ)。
- 要件 032 は「途中から始まる」短い語を止めた。今回は「頭から始まるが、文節の読みの一部だけを覆う」短い語。032 の限界 2 に書いた形そのもの。

## 今の動き (既に分かっていること)
- 関係する場所: `src/Meltype.Core/Composition/CompositionController.cs` の `AlignUserWords`。拍数が 3 未満の登録語は、変換エンジンの文節の頭から始まれば使う (本家 #374・PR #385 の しの → 紫乃 を守るため)。
- 助詞などの表: `CandidateDictionary.Endings` (を・が・は・に・で・と・も・へ・の・や・な・だ・です・から・まで・より・って・とか・さ・ね・よ)。語の後ろの付属語を見る仕組みは、候補辞書がすでに使っている。
- 本家 (yksr-melt/Meltype) の扱い: 本家に無い (この仕組みは Mac 版が足したもの)。

## minimum の要件 (これだけは満たす)
1. 拍数が 3 未満の登録語が、エンジンの文節の頭から始まり、その文節の読みの**先頭の一部だけ**を覆い、残りが「付属語」でないときは、その語を使わない (`CompositionController.CoversOnlyPartOfClause`)。付属語 (`UserWordTrailers`) = `CandidateDictionary.Endings` + 敬称 (さん・くん・ちゃん・さま) + よく続く付属語 (だけ・だった・でした・のこと・ですか・でも・ので・には・では・との・だよ)。**「する」は入れない** (下の得と損)。
2. 使うのは今までどおり: 語だけの文節 (`しゅう`)、語 + 付属語の文節 (`しゅうが`・`しゅうを`・`しゅうと`・`しゅうの|いえ`・`しゅうさん`)、しの → 紫乃 の形、3 拍以上の語 (今までどおり頭でも途中でも使う)。語が複数の文節にまたがるとき・文節の読みが語で始まらないときも今までどおり (変えない)。
3. 使わなくなった語は、文節を Shift+← で縮めれば候補に出る (テストで確認)。
4. 変換エンジンを余分に呼ぶのは、先頭にも短い登録語があり、その後ろが付属語だけでないとき (全体を 1 回。キャッシュ付き)。新しい設定項目は作らない。学習データ・ユーザー辞書は書き換えない。

## 非目標 (今回はやらない)
- ユーザー辞書の登録語を消す・読みを変えること、学習データの書き換え。
- 拍数のしきい値 (3) を変えること。3 拍以上の語は変えない。
- 「する」「した」など動詞の活用を付属語に入れること (人の判断 1)。

## との・だよ を表に足すかの測定 (査読の指摘、2026-11-26。同じ実際の azooKey の区切りの再生)
- 入力 88 件を足して 2,161 件 (登録語 + との・だよ・がきた を、先頭・ごみを・おとうとの の後ろに。登録語の読み 8 つ)。
- だよ: 足すと 登録語 + だよ が使われる (8 読み中 しゅう・じゅん・しょう・ゆう・しの・りょう で、先頭 + ごみを 後 + おとうとの 後)。実在の語 reading + だよ は readings.txt に無く、悪化 0。足した。
- との: 足すと 登録語 + との が使われる (6 読み 16 件)。損は しゅうとの (舅の と読める) だけで 3 件 (先頭・ごみを・おとうとの)。readings.txt に 登録読み + との で始まる語は他に無い。しゅうと + とうの・とめの など 登録語 + と + X の形 (14 件) は足しても元のまま (使われない、直ったまま)。得 16 件 > 損 3 件なので足した。ただし **しゅう を登録した人の しゅうとの は 舅の にならず 登録語 + の ではなく 登録語 + との になる** (損 5)。
## 得と損
- 得: 短い読みを登録した人が、その読みで始まる別の語 (収集・習慣・集中・修正・終了・週末…) を打ったときに、登録語が割り込んで文節が壊れなくなる。大量の打ち比べで 1,614 件が直り、悪化 0 (登録語 + 助詞・敬称・付属語は 0)。登録語は候補から消えない (Shift+← で文節を縮めれば出る)。
- 損 1: 「登録語 + する」は使われなくなる (しゅうする → 秋する にならない)。名前や固有名詞が「する」と続くことは少ないが、ゼロではない。付属語の表に する を足すと、有する・称する・修する のような実在の動詞が同じ形に割れ直るので足していない。
- 損 2: 付属語の表に無いかなが続く文節は、語 + 付属語でも使われない。エンジンが 語 + 付属語 + 別の語 (しゅうがきた) を 1 文節にしたときも、使われない (直さない)。表は `UserWordTrailers` 1 か所で足せる。
- 損 3: 同じ読みの普通の語 (しゅうさん → 集散、しょうさん → 賞賛) は、登録語 + さん になる。
- 損 4: 先頭にも短い登録語があり、後ろに付属語でないかなが続く入力では、変換エンジンを全体で 1 回余分に呼ぶ (結果はキャッシュされる)。しの + 助詞だけの入力は呼ばない。
- 損 5: しゅうとの (舅の) が 登録語 + との になる (上の との の測定)。測定した 8 読み (しゅう・じゅん・しょう・ゆう・しの・さくら・ひなた・りょう) では しゅうと だけが該当した。測っていない読みにも同じ形の損がある: readings.txt で「読み + と」が 1 語になるもの (きょうと・しゅうと・しゅうとめ・しょうとつ など 12 件。査読者の列挙) のうち、その読みを登録している人では「<読み>との」(例: きょう を登録した人の きょうとの = 京都の) が 登録語 + との になる。

## 人の判断
1. **「登録語 + する」が使われなくなることを受け入れるか。** 案 A (推奨): 受け入れる (上の損 1)。案 B: する を付属語に足す。しゅうする・しょうする・ゆうする のような実在の動詞でバグが戻るので推奨しない。決めないままだと: 案 A と同じ。
2. 付属語の表 (敬称・だけ・だった・でした・のこと・ですか・でも・ので・には・では・との・だよ) の範囲。足りない語が実機で見つかれば 1 行で足せる。
