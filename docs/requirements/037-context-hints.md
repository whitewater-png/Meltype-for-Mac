# 037 文脈の手がかり辞書に外れの組を足す (結論: 足さない。見送りを推奨)

## 背景 (誰が、何に困っているか)
- 比較ベンチのかな漢字 120 文 (同音異義語に偏った表) で、Zenzai OFF (azooKey だけ) は 86/120、Zenzai ON は外れが少ない。外れの例: `ねこがないている` → 猫が泣いている (正: 鳴いている)、`しあいにかって` → 試合に買って、`だいがくでけいざいがくをせんこうしている` → 先行、`でしゃしんをとった` → 取った、`きげんまでにていしゅつする` → 機嫌、`きげんがわるいようだ` → 起源。
- 案 D: 文脈の手がかり辞書に外れの組を足せば OFF の人が直るか。足す前に、ベンチの外の文で悪化しないかを測った。

## 今の動き (既に分かっていること)
- 仕組み: `CompositionController.ConvertWithEngine` が、変換エンジンの文節ごとに `ContextRules.Choose(文節の読み, 周りの文字)` を呼び、手がかりが当たった候補を**第一候補に差し替える** (`Prefer`。エンジンの結果に無い候補でも差し込む)。
  - 周りの文字 = 変換する前の確定済みの文字 (OFF は同じ文の最大 10 文字、ON は最大 20 単位) + 同じ変換ボックスの**ほかの全文節** + 後ろの文字。**語順・距離は見ない** (手がかりが周りのどこかに部分一致すればよい)。
  - 文節の読みは、辞書にある**最長の先頭一致**で探す。見つかった規則の手がかりが 1 つも当たらなければ、そこで止まる (短い規則には進まない)。当たった手がかりの数が多い規則が勝つ。同数なら辞書の先の行。
  - 既存の行は `あつい` `とる` のような**辞書形**の読みだけで、活用形 (`とった`・`ないている`) には先頭一致しない。ここが外れの原因の 1 つ。
- **Zenzai ON のときも同じ経路で効く** (Zenzai かどうかを見る条件は無い)。ON の結果を差し替えうる。ON の外れは OFF より少ないので、足した規則の利益は OFF の人だけ、損は ON の人にも出る。
- ベンチ (`--convert-eval`) はエンジンだけで Core のこの後処理を通らない。そのためベンチの外れ 38 文のうち、既存の規則 (いし・かみ・あつい・はやい など) が製品ではすでに直しているものがあるはずで、その数は測っていない (未確認)。

## 試した組 (すべて、読みのキー + 手がかり)
| 組 | 読み → 候補 | 手がかり |
|---|---|---|
| ないて | ないて → 鳴いて | 猫 犬 鳥 蝉 カラス ウグイス ニワトリ |
| かつ | かって・かった → 勝って・勝った (と かってに・かってな → 勝手に・勝手な の止め) | 試合に 試合で 勝負に 大会で 決勝で 優勝 対戦 |
| とった | とった → 撮った | 写真 動画 カメラ スマホ 撮影 |
| せんこう | せんこう → 専攻 | 大学で 学部で 学科で 大学院で 学を (のちに 大学で・大学院で を外した版も試した) |
| きげん | きげん → 機嫌 / 期限 | 機嫌: 悪い いい 良い 直 斜め 損ね。期限: 提出 切れ 締め 守 延長 過ぎ 迫 (のちに いい・提出・過ぎ を外した版も試した) |

## 測り方と限界
- 測った文: 5 組 × (効いてほしい 3〜6 + 効いてはいけない 2〜5 + 意地悪 (手がかりがあるのに逆の意味) 1〜4)。計 80 文 (書き方はリポジトリ外の作業フォルダーの使い捨ての道具。ベンチの文は 1 つも入れていない)。
- 方法: 本物の azooKey (Zenzai OFF / ON) で「前の部分」「後ろの部分」を別々に変換し、その結果を `ContextRules.Choose` (Core の本物。差し替えの条件はテストの偽のエンジンと同じ) に渡して、文節の候補が正解と一致するかを前後で数えた。
- **未確認 (製品の経路で本物のエンジンに通していない)**: 文節の区切りは自分で決めた (エンジンの本当の区切りと違いうる。区切りが合わなかった文は「未整列」として数から外した: 8〜16 文)。周りの文字は前後の部分の変換結果で近似した。実機 (Mac) でも試していない。
- 80 文は自分が書いた。意地悪の文は、手がかりのある文で逆の意味が出る危険を見るために意図して書いたもので、実際の頻度は分からない (コーパスが手元に無い)。ベンチ以外の正解表 (eval/kanji・eval/context・ベンチ本体 ほか約 530 文) で、規則が発火する文を探したところ、ベンチ自身の 6 文以外には 0 件 (悪化も改善も測れない)。

## 結果 (数は文数。fix = 外れ→当たり、worse = 当たり→外れ)
| 組 | OFF: 効く文 fix / 意地悪 worse | ON: 効く文 fix / 意地悪 worse | 普通の「効いてはいけない」文の悪化 |
|---|---|---|---|
| ないて | 4/4 / 3 | 0/4 / 3 | 0 |
| かつ | 4/4 / 1 (+未整列 1) | 0/4 / 2 | 0 |
| とった | 4/4 / 3 | 0/4 / 3 | 0 |
| せんこう | 6/8 / 4 | 0/6 / 7 | 0 |
| きげん (機嫌+期限) | OFF の手がかり調整版 (いい・提出・過ぎ を外した): 14 fix / 0 worse (意地悪を含めて) | 調整版でも ON は fix 2 / worse 2 (手がかりが逆向きに混ざる文) | 0 |

- OFF では、効いてほしい文 (計 22 文) はほぼすべて直る。普通の効いてはいけない文は悪化 0。
- **悪化は、手がかりの語が文のどこかにあり、かつ別の意味が正しい文**で出る。例: 猫が死んでずっと泣いている (→ 鳴いて)、試合に着ていく服を買った (→ 勝った)、写真の整理をして休みを取った (→ 撮った)、学部で学んだことを生かして書類選考に応募した (→ 専攻に)、締め切りを守れなかったので部長の機嫌が悪い (→ 期限が。ON は 機嫌 が正しかった)。手がかりは語順も距離も見ないので、手がかりを絞っても消えない (絞ると効く文も減る)。
- **ON では利益 0 (ON は効く文をすでに当てる) で、損だけが残る。** ON だけ止める仕組みは今は無く、作るなら設定の新設になる (人の判断が要る)。
- きげん は、手がかりを絞れば OFF の悪化は測れた範囲で 0 まで下がった唯一の組だが、ON で混在する文が 2 件悪化した。ベンチでは外れ 2 文 (期限・機嫌) のみ。

## 判断
- **足さない (見送りを推奨)。** 悪化が 1 件でも出る組は入れない、の基準に、5 組とも当たった (きげん は OFF だけなら 0 だが ON で悪化)。
- 得: ベンチ OFF の外れ 38 文のうち、この 5 組が当たる文は最大 6 文 (数十分の 1 の改善。その文そのものに合わせた手がかりなので、ベンチでの数字は信用できない)。損: 手がかりが語順・距離を見ないため、頻繁な語 (買った・取った・泣いて) を差し替える誤りが製品に残る。
- 効果が小さく、悪化を避けられず、ベンチの外で効くことを示す文書もない。**ベンチに合わせた過学習の危険の方が大きい。**
- 人の判断: OFF の人だけが得をする設計 (ON のとき規則を使わない設定の新設) にするか。しないなら見送りのまま。個人が自分で足したい場合は、`%LOCALAPPDATA%\Meltype\dictionaries\contexts.txt` と同じ形式で、利用者のフォルダーの contexts.txt に書ける (docs/USAGE.md)。この文書の表の手がかりを、そのまま試せる。

## 非目標
- Core の仕組み (手がかりの距離・語順・文節の位置を見る) の変更。今回は辞書の行だけを見た。距離を見る仕組みにすれば意地悪の文を避けられる可能性があるが、別の要件にする。
