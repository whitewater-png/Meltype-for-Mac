# 031 変換中に、選んでいる文節の候補を Delete で学習から忘れる

## 背景 (誰が、何に困っているか)
- 学習データに誤った変換が入ると、選び直して学習し直しても直らないことがある。例 (Zenzai OFF): `がくしゅうを` → `がく週を`、`がくしゅうけっか` → `がく週結果`。学習した読み → 文字は、次からその読みの先頭の候補になるため、一度入ると打つたびに出る。
- 実機の報告 (リョウさん、2026-11-25) の「学習する」が「がく週する」になる不具合の**主因は、これではない**: ユーザー辞書の語 (読み `しゅう`) が、語の途中に割り込むこと。こちらは別ブランチ `fix/user-word-mora-threshold` の要件 032 で直す。この要件が扱うのは、**学習データに入ってしまった誤った変換を、1 語だけ忘れられること**。実機の学習データのバックアップのコピーでは、上の `がく週を` が再現し、この機能で消えることを確かめた (下の「記録」)。
- 学習は 2 か所にある。Core の履歴 (`conversions.json`。変換エンジンが文節に区切ったあと、履歴の語を先頭に差し替える) と、azooKey の学習 (Meltype のデータフォルダーの `azooKey/` の `memory.*`)。
- 今の製品には、1 語だけ学習から忘れる方法が無い。あるのは「学習データをすべて消去…」(全消去) と、予測候補を選んでいる間の Delete (本家 #788) だけ。変換中 (文節ごとの候補を選べる状態) の Delete は何も処理されず、確定して Delete がアプリに渡っていた。

## 今の動き (既に分かっていること)
- 関係する場所: `src/Meltype.Core/Composition/CompositionController.cs` (`HandleConversionKey`・予測の Delete の `HandlePredictionKey`)、`ConversionPreferences.cs` (`ConversionHistory`)、`src/Meltype.Mac.Native/Exports.cs`、`mac/Sources/MeltypeIME/Converter.swift`・`NativeCore.swift`・`ConvertEval.swift`。
- azooKey の `forgetMemory(candidate)` は、候補を作っている各語 (`candidate.data`) の**表層形**を集めて、学習の長期記憶 (`LongTermLearningMemory.merge` の `forgetTargets`) から、表層形がその語と一致する項目を消す (**読みは見ない**。azooKey 本体の読みどおり。取り消せない)。そのため、候補を作っている語 (がく・週・を など) の、別の読みで覚えた学習も消えることがある。**文節の読みと表示している文字が、学習した単位に合った候補でないと、消えない** (`しゅう → 週` の候補は表層形 `週` だけを消し、`がく週` という 1 つの語の学習は残る)。実測 (下の「記録」): `しゅう → 週` を忘れさせても `がくしゅうを` は `がく週を` のまま。`がくしゅうを → がく週を` (製品が文節として出す単位) を忘れさせると `学習を` になった。
- 本家 (yksr-melt/Meltype) の扱い: 未確認 (予測の Delete は本家 #788。変換中の Delete は未確認)。

## minimum の要件 (これだけは満たす)
1. 変換中 (Space・Tab などで変換を始め、文節ごとの候補を選べる状態) に、選んでいる文節で Delete (Mac は fn+delete) を押すと、その文節の読み R と、今表示している候補の文字 T について、次をする。Delete は処理したことにする (アプリには渡さない)。
   - 履歴 (`conversions.json`) に R → T があれば消す。**R と T が完全に一致するときだけ** (同じ T の別の読み、同じ R の別の語は消さない。予測の Delete が同じ語を全部消すのとは違う)。
   - 変換エンジン (azooKey) の学習からも、(R, T) の候補を消す (新しい入口 `ForgetConversion`)。履歴に無くても、エンジンには伝える (エンジン側だけに学習があるのが今回の不具合)。
   - Shift つき (Shift+Delete) と、押しっぱなしの自動繰り返し (key repeat) では忘れない。Shift+Delete は今までどおり (確定して Delete をアプリに渡す)。自動繰り返しは Swift の `InputController` が、変換中のものを飲み込んで何もしない (Core はキーの繰り返しを知れないため。変換中でなければ今までどおり通す)。損: 押しっぱなしで続けて忘れることはできない。
   - 変換結果のキャッシュ (Core の `_conversionCache`・`_liveCache`・`_clauseCache`、Swift の `resultCache`) を捨て、その文節の候補を引き直して先頭に戻す。忘れるものが無くても、引き直すだけで害は無い。
2. Native の橋渡し: `meltype_set_forget_conversion` を足す (`meltype_set_reader` と同じ作り。`meltype_init` の引数を変えないので ABI の版数は上げない。古い dylib・古い Swift の組み合わせでは、何も起きないだけ)。
3. Swift: `MeltypeConverter.forgetConversionMemory(reading:text:)`。直近に変換した読みの候補 (`recentCandidates`) から、文字が一致する候補を探して `converter.forgetMemory(candidate)`。覚えた候補に無ければ読みを変換し直して探す。見つからなければ何もしない。
4. 評価の口 (`MeltypeIME --convert-eval`): `--forget <読み>=<語>` (複数回可) と、環境変数 `MELTYPE_EVAL_MEMORY_COPY=<フォルダー>` (azooKey の学習のコピーを一時フォルダーに写して使う。元は読み取りだけ。既定は今までどおり空の一時フォルダー) を足す。

## 非目標 (今回はやらない)
- ユーザー辞書・専門用語集の語を消すこと (消さない。限界として書く)。
- 英語の文節 (打った英字の候補)・ローマ字の再変換 (読みに戻れない) の Delete (今までどおり)。
- 新しい設定項目。UI の案内文 (変換ボックスのヒント) の変更。
- 学習した語の一覧 (「学習した語」の画面) からの削除 (別の要件)。
- 学習の単位をまたいだ忘れ方 (文節の区切りを変えて、学習した単位に合わせて消す手助け)。下の限界のとおり、今は利用者が単位を合わせる。

- 限界 (実測。実機の学習データのコピー、`MeltypeIME --convert-eval`、Zenzai OFF):
  - azooKey の学習は「学習した単位」(1 つの語としての表層形) で持つ。単位と違う区切りの文節で Delete しても消えない。`しゅう → 週` だけを忘れさせても `がくしゅうを` は `がく週を` のまま (単位は `がくしゅう → がく週`)。製品の文節は、エンジンが学習した単位どおりに `がくしゅうを` (`がく週を`)・`がくしゅう` (`がく週`) と区切るので、そのまま Delete すれば消える。Shift+→ で区切りを変えたあとは、間違えた文字が出ている文節で Delete すること。
  - **忘れさせても、ほかの読みの候補が変わることがある。** 上の表のとおり、第一候補は変わらないことが多いが、2・3 番目 (Zenzai OFF の `しゅう=週` だけ) や、第一候補 (Zenzai ON の `しゅう=週` だけで、読み `しゅう` の 週 → しゅう) が変わった。候補を作っている語 (がく・週・を など) の、別の読みで覚えた学習も表層形で消えるため。単位を 2 つ続けて忘れさせた測定 (`がくしゅうを=がく週を` と `がくしゅう=がく週`、OFF) でも、関係の無い 4 読み (`がくしゅうする`・`がくせいがべんきょうする`・`がくもん`・`しゅうり`) の 2・3 番目が変わった。
  - ユーザー辞書・専門用語集の語は消さない。辞書にある同じ語が候補に残ることがある。
  - 忘れたあとの候補は、その文節の読みだけを単独で変換し直したもの。広い文脈 (要件 017 の前の文)・ライブ変換や文全体の変換の結果・`ContextRules` による並びは、効かない。
  - 同じ文字の候補が 2 つ並ぶ (同名候補。例: 辞書の語と、別の読みや区切りで学習した語) とき、Delete は表示している方の 1 つ (読み・文字が一致する Core の履歴と、`recentCandidates` で最初に見つけた azooKey の候補) だけを対象にする。もう一方の学習が残るか消えるかは未確認 (azooKey は表層形で消すので、同じ表層形なら消える見込みだが、実測していない)。
  - 変換中の Delete は、以前は「確定して Delete をアプリに渡す」動きだった。この要件で、忘れる動きに変わる (Shift+Delete・英語の文節・ローマ字の再変換は以前のまま)。
  - Core の履歴の「文脈ルール」(`ContextRules`) による並びは、引き直したあとは文節の単独の変換に戻る。
  - 実機の入力欄・fn+delete・学習ファイルが実機で書き戻されるかは、実機で未確認 (評価の口では、忘れさせたあとに別の変換器で同じファイルを読み直して、`学習を` になることを確かめた)。
