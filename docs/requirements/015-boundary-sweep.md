# 015 判定の悪化を大量の境界例で測る道具

## 背景 (誰が、何に困っているか)
- 判定ロジックや辞書を変える要件では、正解表 (`eval/cases/`) に無い形の悪化を、独立査読が手元の道具で大量の入力を base と比べて見つけてきた。要件 007 の `pre` (89 語・229 形)、009 の `syi` (4,296 語・16,625 形)、012 の `undef` (179 語・18,136 形) は、どれもこの比べ方で見つかった ([AGENT_STATE.md](../AGENT_STATE.md))。
- その道具はリポジトリに無い。作り方の記録 ([IMPROVEMENT_PLAN.md](../IMPROVEMENT_PLAN.md) の W18、要件 011・012 の記録) があるだけで、実装者も査読員も同じ比べ方を再現できない。
- 精度の計画 ([ACCURACY_PLAN_2026-11.md](../ACCURACY_PLAN_2026-11.md)) の Phase 2 は判定ロジックの変更が中心なので、この道具が先に要る。

## 今の動き (既に分かっていること)
- 関係する場所:
  - `tools/eval-compare.sh`・`tools/eval_compare.py` (正解表の前後比較。終了コードの流儀: broken あり 1・問題なし 0・実行の失敗 2)
  - `src/Meltype.Core.Tests/Repro.cs` の `Checks.ExpectAll`・`Checks.Evaluate` (正解表の行を打って Enter した結果。`--expect-all` は今の main と、`--expect-all` が入った後の木にある)
  - `src/Meltype.Core.Tests/Jht.cs` (かな → ローマ字の打ち方の表。ヘボン式が先頭)
  - 辞書: `dictionaries/readings.txt` (JMdict 由来のよく使う語の読み。1 行に「読み」か「読み<TAB>活用の種類」)、`japanese.txt`、`english.txt`
- 前の比べ方の中身 (記録から):
  - W18: 日本語の語 (readings と japanese.txt) を 語・語+desu・語+wo にした約 6 万入力と、1 文字落とし・入れ替えの打ち間違い約 9.4 万入力。
  - 要件 011: 約 372 万入力 (日本語の語の打ち間違い 4 種 + 語の前後の組み合わせ 6 万)。
  - 要件 012: 約 49 万入力 × 7 本の木。`undef` の損失は **語の連結** で出た (`jibundeftotemo` じぶんでとても → じぶんでfとても。〜んで + 余計な `f` / 次の ふ…)。境界例 82 件で見つからなかったのは、語の連結を見ていなかったため。
- 本家の扱い: 本家に同じ道具があるかは未確認 (クラウドからは本家に届かない)。

## minimum の要件 (これだけは満たす)
1. 入力の一覧を、リポジトリの辞書から決まった手順で作れる (同じ木・同じ指定なら、何度作っても同じ一覧)。少なくとも次の組を含む:
   - J1 日本語の語: `readings.txt` と `japanese.txt` の読みを、ローマ字 (ヘボン式の打ち方) にしたもの。単独と、助詞・語尾 (を・が・に・で・の・と・は・も・です) を付けた形。
   - J2 日本語の語の打ち間違い: J1 の単独の形から作った、1 文字落とし・隣どうしの入れ替え・1 文字の重ね打ち・キーボードで隣のキーの 1 文字足し。
   - J3 日本語の語の連結: J1 の語に、よく続く語 (決まった短い一覧) をつないだ形と、そのつなぎ目に余計な 1 キーを足した形。
   - E 英単語: `english.txt` の語の単独と、助詞 (wo・ga・no・desu) を付けた形。
   ローマ字にできない読みは除き、除いた件数を出す。組ごとの件数を出す。
2. 2 つの作業ツリー (base と new) で、同じ入力の一覧を打って Enter した結果を取る (正解表の `--expect-all` と同じ打ち方)。入力の一覧は 1 回だけ作り、両方の木で同じ一覧を使う。**base に新しい入口が無くても動く** (今の main を base にして回せる)。
3. 違いを組と種類に分けて出す:
   - 日本語の損失: J の入力で、base の結果は英字を含まず、new の結果は英字を含む。
   - 英語の損失: E の入力で、base の結果は日本語を含まず、new の結果は日本語を含む。
   - その他の変化: 上のどちらでもない違い。
   件数と例 (組ごとに先頭 20 件ほど) を Markdown で、全件を TSV で出す。
4. 終了コード: 損失が 1 件でもあれば 1、無ければ 0、実行の失敗は 2 (`tools/eval-compare.sh` と同じ流儀)。
5. 使い方 (コマンド・組の作り方・件数と所要時間の目安) を `docs/DEVELOPMENT.md` の評価基盤の節に書く。

## 非目標 (今回はやらない)

- CI で毎回回すこと (時間がかかる。使うかは別に決める)。
- 実機の NSSpellChecker の答えに合わせること (KNOWN_LIMITS.md の K13)。
- 本家の木で回すこと (必要になったら別の要件)。
