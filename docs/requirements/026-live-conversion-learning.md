# 026 ライブ変換の表示のまま Enter で確定したときの学習 (旧番号 018。main の 018 と重なったので 2026-11-23 に付け替えた)

## 背景 (誰が、何に困っているか)
- ライブ変換 (既定 ON) の表示のまま Enter で確定すると、漢字の学習が何も更新されない: azooKey の学習・予測の並びに使う回数・辞書への登録提案の回数。Space → Enter なら全部更新される ([LEARNING_CONTEXT_REVIEW_2026-11-06.md](../LEARNING_CONTEXT_REVIEW_2026-11-06.md) §1。使い捨てのテストで再現。実機は未確認)。
- README の「よく使う語ほど予測で上に出る」「同じ語を 3 回確定すると登録を提案する」「azooKey の学習で使うほど良くなる」が、ライブ変換で確定する人には効きにくい。ライブ変換は既定 ON なので、影響は大きいと見る (推測)。

## 今の動き (既に分かっていること)
- 確定の処理は `src/Meltype.Core/Composition/CompositionController.cs` の `if (converting && !_reconvertRomaji) Learn();` (2998 行付近)。ライブ変換の表示は「変換中」(`converting`) ではないので `Learn()` が呼ばれない。英字 / かなの学習 (`LearnLanguage`) は今も走る。
- 再現の手順 (LEARNING_CONTEXT_REVIEW §1 の R1a〜R1e):
  - R1a: たんいを → 単位を を 1 回学習済み。`tanniwotoru` → Enter で、学習 0 回・予測用の回数は 1 のまま・登録提案の回数 0。
  - R1b: 同じ読みを Space → Enter で、学習 1 回・回数 1 → 2・登録提案の回数 1 (対照)。
  - R1d: ライブ変換 OFF のかなの Enter、Shift+Enter、暗黙の確定 (フォーカス移動など) も学習 0。
  - R1e: `kouengithub` + Space (英語で終わる) は、表示が「講演github」なのに確定が「公園github 」(表示と確定の食い違い。既知)。
- 経緯: 本家の最初の公開コミットから `if (converting) Learn();` の形で、決めた理由の記録は無い。予測の回数と登録提案は Mac 版だけの機能 (IMPROVEMENT_PLAN の P12・P13)。
- 本家の扱い: 本家が今この挙動を変えたかは未確認。

## 案 (LEARNING_CONTEXT_REVIEW §1 の表)

| A (推奨) | ライブ表示を見えたとおりに Enter で確定したとき (暗黙の確定と、英語で終わる Space の経路は除く)、予測用の回数と登録提案の回数だけ数える | README の予測・登録提案の説明どおりになる。すでに出ている語を数えるだけなので害が小さい | ライブ変換は文字列しか返さないので、文節を持っておく変更が Core に要る |

## minimum の要件 (これだけは満たす) — 案 A のとき

3. 暗黙の確定 (フォーカス移動など)、Shift+Enter、英語で終わる Space の経路 (R1e) では数えない。
