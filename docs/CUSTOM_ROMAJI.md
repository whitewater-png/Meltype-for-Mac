# カスタムローマ字表 (romaji.tsv) の書き方

Meltype の変換ボックスで、ローマ字 → かなの変換を自分で決められる機能です (本家 #979、AZIK などの変形ローマ字は #1021)。設定「カスタムローマ字表を使う」(既定は OFF) を ON にして、表のファイルを置きます。

> **AZIK の定義データは、ライセンスの都合で同梱していません。** 利用者が自分で用意する場合は、元のデータのライセンスを確認してください (たとえば fcitx5-anthy の `azik.sty` は GPL-2.0-or-later です。Meltype は GPL-3.0-or-later ですが、定義データを Meltype に取り込んで配るかどうかは、元のライセンスの条件に従う必要があります)。このファイルの例 (`docs/samples/romaji-sample.tsv`) は仕組みを試すための自作の小さな表で、**AZIK ではありません**。

## 置き場所

データフォルダーの `dictionaries/romaji.tsv`。

- Mac: `~/Library/Application Support/Meltype/dictionaries/romaji.tsv`
- ファイルが無い・空・1MB 超・読めないときは、表なし (今までと同じ) です。
- 更新日時か大きさが変わると、次の打鍵で読み直します。再起動は要りません。

## 書き方

1 行 1 定義、`入力` と `出力` を **タブ** で区切ります。`#` で始まる行と空行は無視されます。

```text
# 例 (docs/samples/romaji-sample.tsv)
;	っ
k;	かん
st	した
```

- 入力: 英字 (大文字は小文字として扱う) と、下の記号。8 文字まで。数字は使えません。
- 出力: かな・記号など。16 文字まで。前後の空白は削られます (空白だけの出力は書けません)。制御文字とタブは不可。
- 不正な行はその行だけ無視され、警告がログに残ります。同じ入力が複数あるときは後の行が勝ちます。
- 長いキーが優先されます (最長一致)。表のキーは、`n` + 子音 → ん や 同じ子音の連続 → っ の固定ルールより先に使われます。
- 短いキーと長いキーがあるとき (`ka` と `kaku`) は、長いキーに届く可能性がある間は待ち、届かなければ短いキー + 標準の綴りで進みます。

## キーに使える記号

`;` `:` `[` `]` `@` `-` `,` `.` `/` `'` `^` `\` の 12 種です。数字・括弧 `( )`・`{ }`・引用符 `"`・`!` `?` `~` `#` などは、表のキーにすると数字の単位や括弧の幅などの規則とぶつかるため、使えません (その行は無視されます)。

記号キーの扱い:

- 打った記号で表のキーが揃う (または長いキーの途中になる) ときだけ、表を優先します。キーに届かない記号は、今までの規則 (`、` `。` `ー` `「」`、`z` + 記号、英語の区切り、パスなど) のままです。
- 表が無い・OFF・記号入りのキーが無い表では、記号の扱いは今までと完全に同じです (テストで固定)。
- 記号をキーにした表を使うと、その記号の既定の働き (`;` `:` `@` など) は、表のキーが揃う場面で表に置き換わります。たとえば `@` をキーにすると、語頭や日本語の直後の `@` (`@name`) は表の出力 (例: ん) になります (`taro@example.com` のように英字の後ろは、実測では変わりませんでした)。一方、`a@` や `t-` のように**英字と記号を組み合わせたキー**は、メールアドレスやドメインを壊します (例: `t-` を `W` にすると `ryo@t-online.de` が `ryo@Wonline。で` に)。`.` `/` をキーにすると小数 (`3.14`) やパス (`C:/dev`) も変わります。必要なら、その記号を表から外してください。
- `z` の直後の記号 (`z.` = …、`z[` = 『) は、`z` + その記号がキーでない限り、今までの規則が先です。
- キーの途中 (`;a` に対する `;`) で確定すると、記号は今までの記号の規則、英字は標準の綴りで確定します。キー待ちの間の表示は、記号がそのまま (`[` など) 見えることがあります。
- BackSpace は、表キーでできた単位を 1 打鍵だけ戻します (`k;` → `k`)。

## 英語判定との関係

通常、英語かどうかの判定は表を見ません。例外は 1 つだけです。

- 区間の英字全体が、**標準の綴りでは最後まで読めず、表のキーを使うと最後まで読める**とき (例: 表に `st` `kt` があるときの `stkt`)、それが英単語として知られていなければ日本語 (したこと) にします。
- 英単語として知られている語 (`string` `ring` `apple` `stop` `stereo` など)、標準の綴りで読める語、表のキーを 1 つも使わない語は、今までの判定のままです。表のキーで始まるだけで最後まで読めない語 (`stktx` のように読めない文字が余る場合) も変えません。なお表が `st` `kt` のとき `stkta` は `st` + `kt` + `a` で最後まで読めるので、`stkta` は日本語 (したことあ) になります。

- 実機のスペルチェッカーだけが英単語と言う短い綴り (`hast`) の後ろに表のキーが続き、全体が表でだけ読める (`hastkt` = ha + st + kt) ときも日本語にします (`kyouhastkt` → きょうはしたこと)。同梱の英単語と学習した語は対象外です。

## 制限

- 変換ボックス (Mac の IME) だけが対象です。Windows の `CompositionService`・辞書管理画面などには配線していません。
- 同じ表のキーを複数の文字で打ち分けるような、キー配列そのものの切り替え (Dvorak など) は扱いません。配列に依存するキー名は、実際に入力される文字 (`;` `:` など) で書いてください。
- 打鍵のたびに表の更新日時を確認します (ON のとき)。
