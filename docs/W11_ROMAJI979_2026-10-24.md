## 実装範囲

- 設定 `CustomRomajiTable` (既定 **OFF**)。Mac 設定画面「入力」にトグル 1 つ。説明文に置き場所を書いた。
- 表の置き場所: データフォルダーの `dictionaries/romaji.tsv` (Mac は `~/Library/Application Support/Meltype/dictionaries/romaji.tsv`)。
  - W9 は `romaji.txt` としていたが、同梱の `dictionaries/*.txt` (辞書のマージ読込) と混ざらないよう `.tsv` にした。
- 形式: 1 行 `入力(英字)<TAB>出力`。`#` 行・空行は無視。入力は小文字化。長さは入力 8 文字・出力 16 文字まで。
- 読込 (`Detection/RomajiTable.cs`): 不正行 (タブなし・入力が空・非英字・長すぎ・出力が空/制御文字) は**その行だけ無視**して警告ログ。重複キーは**後の行が勝つ** (W9 案どおり、警告ログ)。有効な行が 0・ファイルなし・読めない・1MB 超は表なし = 従来どおり (例外にしない)。更新日時と大きさで読み直す (再読込は次の打鍵で反映)。
- 適用 (`RomajiDetector`): 位置 i で表のキーを最長一致 (最大長は表から算出)。**ん・っ の固定ルールより先**に照会するので `kk`/`nk` も表が勝つ。一致するキーが無く、残りが表のキーの先頭 (`ngh` に対する `ng`) なら、固定ルールを当てずに途中として待つ。
- 適用先は「かなにする側」だけ: 変換ボックスの表示・単位の作成 (`CompositionText.Normalize`/`PendingText`) と F6 などの読み (`CompositionController` の 2 か所)。**英語判定 (`Analyze`・`AnalyzeFragment`・`ScoreEngine`・辞書の見出し語・校正・辞書登録) は表を見ない**。`st`=した のような表でも、`string` や `ring` の判定は変わらない (テスト済み)。

## 制限 (正直に)

1. **保留なし**: キーが全部揃ったときだけ置換する。表に `ka` と `kak` があると、`ka` が先に `か` に確定し `kak` には伸びない (`かk`)。`ry`=らい と `ryp`=りょう なら、`ry` を打った時点で `らい` に確定済みなので、`ryp` と続けて打っても `らいp` になる (W9 §3 の「`ry` を表示しつつ `p` で置き換え」は未実装 = Phase 1 後半の B1)。**ConvertForDisplay に `ryp` を一括で渡せば `りょう`**。キーが他のキーの接頭辞でも途中で確定しない形 (`ngh` に対する `ng`、`ryp` を `ry` が無い表で使う) は動く。
2. 英字キーのみ。`;` `[` `]` `-` `:` などの非英字キーは行ごと無視 (W9 A4 は未着手)。
3. **英語判定側は表を知らない**: 日本語と判定された語の中でだけ表が効く。表のキーでしか読めない綴り (`st` など) は、英語と判定されれば英字のまま。日本語/英語の行き来で「表で読める綴りを日本語寄りに判定する」ことはしない (Phase 3 / C1)。
4. 表を使う設定が ON のとき、表のキーの先頭になる英字列 (`ng` など) は、末尾で確定 (Space) すると `ん`+`g` ではなく英字のまま残る。
5. 変換ボックス (MeltypeSession 経由の IME・Mac) だけ。Windows の `CompositionService`・`ScoreEngine.CreateDefault`・辞書管理画面には配線していない (`CustomTable` を設定した検出器だけで有効)。
6. AZIK 定義は同梱しない (GPL-2.0-or-later のため。W9 §7)。
