# W11 — 本家 #979 カスタムローマ字表 (Phase 1 最小版)

2026-10-24。ブランチ `feat/romaji979`。設計の元は [W9_ROMAJI_INVESTIGATION_2026-10-23.md](W9_ROMAJI_INVESTIGATION_2026-10-23.md) の Phase 1。**push 前・実機未確認**。

## 実装範囲

- 設定 `CustomRomajiTable` (既定 **OFF**)。Mac 設定画面「入力」にトグル 1 つ。説明文に置き場所を書いた。
- 表の置き場所: データフォルダーの `dictionaries/romaji.tsv` (Mac は `~/Library/Application Support/Meltype/dictionaries/romaji.tsv`)。
  - W9 は `romaji.txt` としていたが、同梱の `dictionaries/*.txt` (辞書のマージ読込) と混ざらないよう `.tsv` にした。
- 形式: 1 行 `入力(英字)<TAB>出力`。`#` 行・空行は無視。入力は小文字化。長さは入力 8 文字・出力 16 文字まで。
- 読込 (`Detection/RomajiTable.cs`): 不正行 (タブなし・入力が空・非英字・長すぎ・出力が空/制御文字) は**その行だけ無視**して警告ログ。重複キーは**後の行が勝つ** (W9 案どおり、警告ログ)。有効な行が 0・ファイルなし・読めない・1MB 超は表なし = 従来どおり (例外にしない)。更新日時と大きさで読み直す (再読込は次の打鍵で反映)。
- 適用 (`RomajiDetector`): 位置 i で表のキーを最長一致 (最大長は表から算出)。**ん・っ の固定ルールより先**に照会するので `kk`/`nk` も表が勝つ。一致するキーが無く、残りが表のキーの先頭 (`ngh` に対する `ng`) なら、固定ルールを当てずに途中として待つ。
- 適用先は「かなにする側」だけ: 変換ボックスの表示・単位の作成 (`CompositionText.Normalize`/`PendingText`) と F6 などの読み (`CompositionController` の 2 か所)。**英語判定 (`Analyze`・`AnalyzeFragment`・`ScoreEngine`・辞書の見出し語・校正・辞書登録) は表を見ない**。`st`=した のような表でも、`string` や `ring` の判定は変わらない (テスト済み)。

## 制限 (正直に)

1. **保留なし**: キーが全部揃ったときだけ置換する。表に `ka` と `kak` があると、`ka` が先に `か` に確定し `kak` には伸びない (`かk`)。`ry`=らい と `ryp`=りょう なら、`ry` を打った時点で `らい` に確定済みなので、`ryp` と続けて打っても `らいp` になる (W9 §3 の「`ry` を表示しつつ `p` で置き換え」は未実装 = Phase 1 後半の B1)。**ConvertForDisplay に `ryp` を一括で渡せば `りょう`**。**標準で完結する綴りの先頭にあたるキーは、キーボードでは届かない (保留機構 B1/B2 が前提)**: 表が `kak` だけ (`ka` 無し) でも、キーボードで `kak` と打つと `ka` が先に `か` になり `かk` (`tsuk`・`kyak`・`shik` も同じ)。API に一括で渡したときだけ `かく`。H1 (標準で読める残りは待たない) とのトレードオフ。`Limitation_Keyboard_KeyThatIsPrefixOfStandardSpelling_Unreachable` が現状を固定しており、B1 実装時に赤になる。キーが他のキーの接頭辞でも途中で確定しない形 (`ngh` に対する `ng`、`ryp` を `ry` が無い表で使う) は動く。
2. 英字キーのみ。`;` `[` `]` `-` `:` などの非英字キーは行ごと無視 (W9 A4 は未着手)。
3. **英語判定側は表を知らない**: 日本語と判定された語の中でだけ表が効く。表のキーでしか読めない綴り (`st` など) は、英語と判定されれば英字のまま。日本語/英語の行き来で「表で読める綴りを日本語寄りに判定する」ことはしない (Phase 3 / C1)。
4. **表のキーの途中扱い (H1 修正後の正確な範囲)**: 表のキーの先頭になる英字列は、**標準の綴りで最後まで完結して読めないとき**だけ、途中として待つ。表に `kak` だけあって `ka` が無ければ、`ka` は標準で `か` と読めるので待たずに `か` にする (`ka`+Space/Enter も `か`)。`ng` のように標準でも途中 (`ん`+`g` の `g` が未確定) になる列は、`ngh` を持つ表では待つ。この待ちのまま確定 (Space/Enter、F6、再変換) すると、`n`/`nn` 以外の残りは 1 文字ずつ英字のまま出る (`ng` → `ng`、`ん`+`g` にはならない)。表に `ng` 自体を定義すればこの問題は起きない。
5. 変換ボックス (MeltypeSession 経由の IME・Mac) だけ。Windows の `CompositionService`・`ScoreEngine.CreateDefault`・辞書管理画面には配線していない (`CustomTable` を設定した検出器だけで有効)。
6. AZIK 定義は同梱しない (GPL-2.0-or-later のため。W9 §7)。
7. **空白だけの出力は定義できない**: 出力は前後の空白を削る (`Trim`) ので、空白だけの出力は「出力が空」として行ごと無視される。
8. **打鍵ごとに stat が走る (ON のとき)**: 表の更新を拾うため、変換ボックスの解析のたびにファイルの更新日時と大きさを見る (内容の読み直しは変更があったときだけ)。読み込みに失敗したときは次の打鍵で再試行する。通常ファイル以外 (FIFO・デバイス・大きさ 0) と 1MB 超は読まない。
9. **表を切り替えると古い区間が残りうる**: 表を差し替えても、すでに画面に出ている区間は次の打鍵まで古い表の結果のまま。
10. **英語判定と単位構築の一部は表を見ない箇所がある (未検証)**: 判定は表を使わない方針だが、単位 (ユニット) の組み立てなど判定以外の経路に、表を見ない箇所が残っているかは網羅して確認していない。
